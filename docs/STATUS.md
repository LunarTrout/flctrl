# Состояние библиотеки

Дата: 3 ноября 2026. Всё ниже проверено прогоном, а не заявлено.

## Что умеет слух

| слой | модуль | что даёт |
|---|---|---|
| фронты | `audit.py` | 10 фронтов против коридора референсов: крест, LDR, резкость, шум, атаки, клипинг, моно-потеря, полосы спектра, стерео |
| стена | `wall.py` | провалы по 9 полосам и секциям относительно медианы трека; толщина стены |
| стерео | `pan.py`, `panplan.py` | позиция и ширина по полосам; план движения панорамы по секциям |
| слышимость | `partial.py` | ISO 532-2: `A = N_partial/N_solo`, по полосам и **по секциям** |
| разборчивость | `speech.py` | SII по ANSI S3.5, 18 полос, по активным кадрам, с калибровкой по мастеру |
| эффекты | `effects.py` | RT60/EDT/C50, THD, дакинг |
| баланс | `balance.py` | цель как ансамбль k ближайших референсов |
| цели | `snrtargets.py` | жанровые отношения по 7 областям из корпуса |
| решения | `decide.py` | правки: инструмент × полоса × участок × дБ, с капом и контролем усиления |
| проверка | `simulate.py` | правки применяются к стемам, микс пересобирается, мерится заново |
| отчёт | `report.py`, `checks.py` | один вызов, реестр из 12 проверок, покрытие и причины пропусков |

## Проверенные числа

- **Точность правки:** подъём на 3 дБ даёт +3.00 дБ в измерении (до исправления
  единиц было +0.7 — считали в единицах громкости, а не уровня).
- **Разборчивость:** наш SII 0.21 против 0.015…0.32 у референсов — вокал в норме
  жанра, слабое место 5 кГц.
- **Стена:** толщина 1.00 против жанра, единственный провал — 12 кГц, −8.4 дБ.
- **План на реальном материале:** бас 0.091 → 0.310 по слышимости после
  применения (доля 3.5 → 13.1 %), гитары 0.536 → 0.447 (доля 88.2 → 77.2 %).
- **Контроль усиления:** план из 12 правок даёт +3.4 дБ миксу и честно
  предупреждает об этом.
- **Кэш:** повторный отчёт 1.8 с вместо 12.3 с, отчёты побайтно идентичны.

## Тесты

`python tools/run_tests.py` — 17 файлов, 14 запускаются офлайн, **0 провалов**.
Живые тесты FL включаются флагом `--fl` и требуют тестовый проект.

## API FL

Работает вживую (проверено на открытом проекте): чтение состояния, дорожки,
плагины, маршруты, уровни, запись фейдеров и панорамы, живая вставка и удаление
родных плагинов, создание и удаление дорожек, запись параметра без остановки
транспорта, самодиагностика (`fl_doctor` — 10 из 10, отклик 2–3 мс), карта API
(`fl_capabilities`).

## Что осталось непроверенным и почему

1. **Применение плана в FL как автоматизации** (`mixer.automateEvent`).
   Функция в API есть, но вызов пишет в проект — проверять можно только на
   тестовом `small.flp`, а открыт рабочий `vers1`.
2. **Живая вставка стороннего VST** внутрь `Fruity Wrapper`. Родные плагины
   ставятся и удаляются, VST — нет; четыре пути проверены, нужен отдельный
   стенд, чтобы не рисковать рабочим проектом.

## Честные ограничения модели

- Цели считаются относительно «остального микса» (мастер минус стем). Набор
  стемов может быть неполным, поэтому суммарный подъём по всем ролям не обязан
  быть нулевым — это свойство метода, а не ошибка.
- Правки в `simulate` применяются ко всему стему, а не к своему участку: это
  проверка направления и величины, а не копия будущей автоматизации.
- Разделение референсов не различает guitars и keys — обе роли берут цель у
  `other`, это записано в `docs/snr_baseline.json`.
