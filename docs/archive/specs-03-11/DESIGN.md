# DESIGN: как устроена библиотека и почему именно так

Точка входа. Здесь — принципы и связи; детали лежат в документах, на которые
ссылаются разделы.

- `docs/SPEC-CONTEXT.md` — полный реестр того, чего не хватает (звук, время,
  провенанс, плагины, восприятие, знание, инфраструктура) и порядок работ.
- `docs/ARCHITECTURE-PLAN.md` — слои кода и что с чем дублируется.
- `docs/DESIGN-BALANCE.md` — модель баланса и цели из корпуса.
- `docs/ROADMAP.md` — что сделано, что дальше.
- `docs/ARCHIVE.md` — указатель на все прежние документы (`docs/archive/vers1`):
  требования, состояние, спецификации FL, методология сведения.

## 1. Требование

> Из микшера в лайве получать **все дорожки** и понимать, из чего они состоят:
> из каких **клипов и MIDI**, и **в какой момент их времени**.

Развёрнуто: по любой дорожке в любой момент времени **знать состав** (клипы,
ноты, хвосты, локальное время источника), **знать обработку** (плагины,
автоматизация), **знать восприятие** (частичная громкость, маскировка,
транзиент, стерео) и **уметь менять** с предсказуемым результатом и проверкой
числом.

Библиотека — не «умный сведенщик», а прибор: она достаёт факты и умеет их
сравнивать. Решения принимает вызывающий (человек или модель через MCP).

## 2. Принципы

1. **Факты, не советы.** Инструмент возвращает числа, единицы, базу сравнения и
   покрытие. «Что с этим делать» — не его дело.
2. **Сравнение вместо объяснений.** Любые две картины имеют одну форму, поэтому
   сравниваются дельтой по одним осям. Текст «это значит…» не нужен.
3. **Инвариантность.** Метрика не должна зависеть от числа дорожек и общего
   уровня — иначе сравнение с референсом бессмысленно.
4. **Провенанс.** У числа всегда есть адрес: из чего сложилось, чем обработано,
   где послушать.
5. **Пропуск виден.** Отсутствие данных — явная пометка, никогда не ноль.
6. **Правило №0: сначала ресёрч, потом реализация.** И никаких слепых `sleep`.

## 3. Куб: одна форма для всех картин

```
оси: время (сэмпл → такт) × дорожка (→ роль) × полоса (ERB) × метрика
```

Матрица из потока — срез `rms[время, дорожка, полоса]`. Спектр файла — тот же
срез, посчитанный иначе. Референс — такой же куб, другой источник.

**Картина = проекция куба**, сравнение = дельта по тем же осям. Провал вниз
бесплатный: клетка → источники (клипы, ноты, хвосты) → обработка → сырой отрезок.

Подробно: `SPEC-CONTEXT.md` §2.5.

## 4. Гранулярность: у референсов нет 32 дорожек

Решено ролями и отношениями, а не выравниванием дорожек:

- `roles.py` приводит проект к `drums / bass / guitar / keys / vocals / other`;
- референсы существуют только на уровне ролей;
- сравнение — на **самой грубой общей гранулярности** (референс ↔ мы — по ролям,
  наш «до/после» — по дорожкам);
- метрика инвариантна: `роль / остальное`, а не абсолютная громкость;
- аддитивные метрики внутри роли суммируются, неаддитивные считаются как
  «роль против остального»;
- отсутствие данных — пропуск, не ноль.

## 5. Как обходим разделение референсов

Разделение референса на стемы — слабое звено (плохое качество, ошибки больше
эффекта). Поэтому **основной путь — обратная задача** (`invmix.py`):

```
референс → цели микса (области, резкость, крест, стерео)
наши дорожки (настоящие) → ищем гейны ролей
сумма с гейнами → те же метрики → расстояние до цели минимизируется
```

Уравнений больше, чем неизвестных — ответ проверяем. **Цели по ролям получаются
как побочный продукт решения**, а не измерением стемов.

Стемы референса — только перекрёстная проверка, с метрикой качества
(ошибка реконструкции + протечка). `docs/snr_baseline.json` из стемов подлежит
замене или пометке как приблизительный.

## 6. Главное — записать

Всё, что «насколько далеко от жанра», уже считается по файлам существующими
инструментами (`audit`/фронты, `snrtargets`, `wall`, `transients`, `harmony`).
Не хватает самих файлов дорожек.

Поэтому приоритет: **поток аудио с дорожек (в стерео) и его запись на диск**,
затем точные позиция и темп, затем провенанс. Восприятие — производное: те же
метрики считаются по записи вместо стемов.

## 7. Поверхность для вызывающего

Сейчас 77 MCP-инструментов — это налог на контекст. Целевая поверхность — 10
групп, а не 77 тулов:

```
state  mixer  plugins  transport  render  record  hear  refs  decide  system
```

Внутри — примитивы двух видов: **кадр** (`frame(metric, ...)`) и **сравнение**
(`diff(a, b)`). Метрика становится строкой в реестре, а не отдельным
инструментом.

Карта операций — `docs/OPS.md` (ещё не написан), из неё же генерируется `help`.

## 8. Что уже есть

Микшер (чтение, роутинг, слоты, вставка/удаление плагинов, дорожки), параметры
с подбором шкалы по подписи, `apply.plan`, движение в реальном времени, слух по
файлам (фронты, 240 полос Барка, маскировка, секции, стена, частичная
громкость, SII, транзиенты, гармония), корпус и цели, отчёт с покрытием, карта
клипов (647 из `.flp`), рендер CLI.

Чего нет — `SPEC-CONTEXT.md` §3, 50+ позиций с приоритетами.

## 9. Порядок

1. поток аудио с дорожек + запись;
2. точная позиция в сэмплах и темп;
3. провенанс (смещение в сэмпле, свежесть карты);
4. ноты из паттернов;
5. хвосты и мастер;
6. восприятие по записанным дорожкам;
7. метры плагинов и автоматизация.

## 10. Критерий готовности

Первый рубеж: **любой участок любой дорожки пишется в файл без рендера проекта
и без соло-проходов**, с точной позицией и темпом.

Полная система отвечает числами без рендера на шесть вопросов: что звучит и
откуда; насколько слышно; кто маскирует; что делает плагин; насколько далеко от
жанра; что будет, если изменить.
