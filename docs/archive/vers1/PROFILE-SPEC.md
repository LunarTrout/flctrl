# Профиль микса: какие подходы применяются и какие данные получаются

Документ описывает **полный профиль**, который библиотека снимает с трека, и метод
за каждым полем. Примеры значений — реальные, с рендера `vers1` (участок 60–90 с).

## 0. Уровни профиля

Профиль снимается на четырёх уровнях, и один и тот же движок работает на всех:

| Уровень | Что это | Как задаётся |
|---|---|---|
| точка | 4 секунды вокруг момента | `--at 112.5` |
| секция | произвольный отрезок | `--section 95:140` |
| такт / сетка | по кадрам 50 мс | непрерывная кривая |
| трек целиком | весь файл | `--section 0:352` |

Скорость: 30 с — 0.5 с, весь трек 352 с — 6.6 с.

## 1. Структура проекта (что вообще есть)

| Поле | Метод | Пример |
|---|---|---|
| дорожки микшера, имена, громкость, панорама, mute/solo | живой API FL + разбор `.flp` | 32 дорожки |
| каналы рэка, привязка к дорожке | событие `0xE5` (20 байт) | 142 канала |
| плагины по слотам + **все параметры** | событие `0xD5`, живой `plugins.*` | Pro-L 2 ×9, Fortin ×4 |
| маршруты и уровни посылов | `0xE7`/`0xEB` | DRUMS→24, GTR L→17 |
| плейлист: клипы, позиции, края | PyFLP_v2 | 779 клипов |
| ноты: позиция, канал, нота, velocity | событие `0xE0` (24 байта) | 4684 ноты |
| автоматизация | событие `0xEA` (21 + 24·N) | в работе |

## 2. Уровни и громкость

| Поле | Метод | Пример |
|---|---|---|
| LUFS интегральная | BS.1770 (pyloudnorm) | −12.3 |
| пик, true peak | выборка / передискретизация | −1.2 dBFS |
| crest factor | пик / RMS | 14.6 dB |
| **LDR** (микродинамика) | std коротких RMS (3 с) / общий RMS, через кумулятивную сумму | −16.6 dB |
| баланс стемов относительно суммы | доли энергии по стемам | барабаны −12.6 dB |

## 3. Перцепция (не dB, а восприятие)

| Поле | Метод | Пример |
|---|---|---|
| громкость N | ISO 532-1 Zwicker, по 28 третьоктавам | 76.8 сон |
| уровень | фоны | 102.6 |
| **удельная громкость N′(z)** | 240 полос Барка | матрица 240 × кадры |
| **резкость** | DIN 45692 (`din`/`aures`/`bismarck`) | 1.62 acum (p95 1.80) |
| roughness, tonality, fluctuation | ECMA-418-2 | по запросу |
| STI (разборчивость) | модуляционная передача | по запросу |

Калибровка: все файлы приводятся к 90 dB SPL суммарно, иначе компрессия громкости
Zwicker'а делает цифры несравнимыми между треками.

## 4. Спектр и полосы

| Поле | Метод | Пример |
|---|---|---|
| 28 третьоктав | БПФ 4096, окно Ханна, 50 мс кадр | по кадрам |
| доли 7 областей Барка | интеграл N′ по диапазонам | sub 11 / bass 16 / lowmid 15 / mid 20 / upmid 21 / pres 12 / air 5 % |
| октава 4 кГц | доля энергии октавы | −11.2 dB |
| наклон LTAS | линейная регрессия по log-частоте | по запросу |

## 5. Стерео

| Поле | Метод | Пример |
|---|---|---|
| корреляция L/R | Пирсон по выборке | 0.74 |
| **side/mid** | 10·log10(E_side/E_mid) | −8.3 dB |
| ширина | sqrt(E_side/(E_mid+E_side)) | 0.36 |
| потеря в моно | отношение mid к сумме | −0.6 dB |

## 6. Маскировка

| Поле | Метод | Пример |
|---|---|---|
| доли N′ по стемам | Demucs-стемы, та же модель громкости | гитары+other 64–70 % середины |
| кросс-адаптивная маскировка | разность N′ в каждой полосе Барка | по запросу |

Ограничение: стемы **нельзя суммировать** (Σ N′ = 1.55× микса) — доли валидны,
абсолютная сумма нет.

## 7. Разборчивость вокала

| Поле | Метод | Пример |
|---|---|---|
| STOI | стем как «чистый», микс как «испорченный» | 0.677 (GRIMA 0.557) |

## 8. Узнавание (не измерение, а «на что похоже»)

| Поле | Метод | Зачем |
|---|---|---|
| метка инструмента | PANNs / CLAP эмбеддинги + кластеризация | атрибуция 142 каналов |
| близость к референсу | косинус эмбеддингов | поиск похожего места |
| стиль сведения | MIXSTYLE FXencoder, 2048-мерный, 0.17 с | «сведено ли так же» |
| оценка качества | Audiobox Aesthetics (CE/CU/PC/PQ) | 7× реального времени |

## 9. Сравнение с референсами

| Поле | Метод |
|---|---|
| коридор | min/max по каждому полю из набора референсов |
| позиция | (наш − min)/(max − min) |
| вердикт | ниже / в коридоре / выше |
| сопоставление | только однотипные секции |

Пример: 15 метрик, вне коридора 1.

## 10. Временная структура

| Поле | Метод |
|---|---|
| секции | смена энергии и тембра (автосекции) |
| онсеты | спектральный поток |
| темп, сетка | из проекта |
| непрерывные кривые | любое поле по кадрам |

## Как выглядит профиль целиком (пример)

```
ПРОЕКТ   vers1.flp  155.5 BPM  32 дорожки / 142 канала
СОСТАВ   9 Pro-L 2, 4 Fortin, 3 Kontakt, SD3, EZbass, 9 Fruity Comp
ГРОМКОСТЬ  N 76.8 сон | фоны 102.6 | LUFS −12.3 | crest 14.6 | LDR −16.6
РЕЗКОСТЬ   1.62 acum (p95 1.80)
ПОЛОСЫ     sub 11 | bass 16 | lowmid 15 | mid 20 | upmid 21 | pres 12 | air 5 %
СТЕРЕО     corr 0.74 | side/mid −8.3 dB | ширина 0.36
МАСКИРОВКА гитары+баян 64–70 % середины | барабаны 6–7 % | бас 47 % субниза, 12 % громкости
ВОКАЛ      STOI 0.677 — не забит, выпирает
КОРИДОР    15 метрик, вне: 1 (air выше GRIMA/Wintersun/Finntroll)
```

## Правила, зашитые в профиль

1. `measure` решает, `describe` ищет — числа из эмбеддингов не идут в решения о балансе.
2. Стемы не суммируются.
3. Гитарный стем сепаратора (SDR 3 дБ) не используется для выводов о балансе.
4. LUFS не описывает узкополосные источники — рядом всегда центроид и доли полос.
5. Сравнение только однотипных секций.
6. MOS-метрики для речи к музыке не применяются.
