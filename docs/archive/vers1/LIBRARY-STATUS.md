### Единая библиотека: `fl_lib.py`

```python
import fl_lib as fl

fl.state.tracks()          # живой микшер: имена, громкость, панорама, эффекты
fl.state.channels()        # каналы рэка
fl.state.plugins()         # плагины по слотам
fl.state.playlist(flp)     # клипы из файла (проверено: 98 записей)
fl.state.automation(flp)   # автоматизация (проверено: 4 таргета 'project', по 2 точки)

fl.hear.measure(wav, 60, 90)   # N, фоны, резкость, LUFS, crest, LDR, стерео
fl.hear.curve(wav)             # непрерывные кривые: N(t), N′(z) 240 полос
fl.hear.profile(wav)           # кэш всего профиля (один расчёт на файл)
fl.hear.bands(wav)             # по 240 полосам: уровень, ширина, модуляция
fl.hear.compare(wav, refs)     # коридор из нескольких референсов

fl.act.volume(track, v)        # правки вживую
fl.act.pan(track, v)
fl.act.param(track, slot, idx, v)

fl.sim.load(wav, a, b)         # песочница: любые операции по порядку
fl.sim.run(x, fs, ops)         # ops: gain / hpf / lpf / eq / comp / sat / pan / vst3
fl.sim.compare(x, y, fs)       # замер до и после
fl.sim.vst(path, bands=..., params=...)   # готовый оператор настоящего VST3

fl.predict.change(mix_prof, track_prof, gain_db, eq)   # предсказание без применения
fl.predict.lines(before, after)                        # что изменится

fl.create.plugin(fst, ins, slot)    # вставка плагина (+ перечитывание)
fl.create.clone(src, sslot, dst, dslot)
fl.create.reload()
fl.create.render(flp)               # офлайн-рендер (медленно, для финала)
fl.hear.offline(flp)                # рендер один раз с кэшем по состоянию файла
fl.hear.at(flp, start, dur)         # замер любого места из кэша
fl.hear.live(seconds, start, track) # быстрый цикл: играем и пишем, без рендера
```

## Что именно невозможно и почему

1. **Вставка плагина вживую через API.** Функции нет ни в одном модуле; `REC_*` дают только параметры загруженных; браузер застревает; `ui.keySeq` в 25.2.5 отсутствует; `selectBrowserMenuItem` не грузит; `os.startfile` на `.fst` игнорируется.
2. **Хуки и вызов функций по адресу изнутри FL.** Скрипт исполняется в субинтерпретаторе: `ImportError: module _ctypes does not support loading in subinterpreters`. Значит нужен внешний процесс (отладчик/инжектор).
3. **Создание канала и клипа.** Нет конструктора объектов; вKindA-подобные проекты делают это постингом сообщений окну.

## Что дал реверс движка

- Настоящий код: `FLEngine_x64.dll` (55 МБ, Delphi); `FL64.exe` — загрузчик 1.1 МБ; экспорт всего 3 символа, все дельфийская болванка.
- Кандидаты: `TVST3Plugin.LoadPlugin` @ RVA `0x006E3200`; обработчик «insert effect plugin» @ `0x009B6BE0`; фабрика класса @ `0x006FA0B0`.
- Настоящий `LoadLibraryExW` + `VSTPluginMain` — в `Fruity Wrapper_x64.dll` (`VSTPluginMain` @ `0x3A6F10`).
- Отчёт: `_analysis/FL-REVERSE.md`; инструмент: `flstudio-mcp/tools-local/fl_re_scan.py`.
- Для вызова нужен снимок регистров в момент вставки — работа идёт под x64dbg на маленьком проекте.

## Ограничения измерений (зашить в решения)

- **Калибровка только по всему треку, никогда по отрезку.** Если приводить каждый
  отрезок к 90 фонам отдельно, тишина «подтягивается» до нормальной громкости:
  пустой участок показывал N=82 при LUFS = −inf. Смещение считается один раз по
  энергетическому среднему всего файла и применяется ко всем его отрезкам.
  Проверено: вступление 0–30 с даёт N=0 и фоны 3, плотные секции — N=77–79.

- Стемы не суммировать: Σ N′ = 1.55× микса; доли валидны, сумма — нет.
- Гитарный стем сепаратора: SDR 3 дБ → для баланса гитар непригоден.
- MOS-метрики для речи к музыке не применять.
- Энергетические анализаторы переоценивают низ — не арбитр.
- Сравнивать только однотипные секции.
- LUFS не описывает узкополосные источники (Shi/Reiss 2025) — добавлять центроид и f0.
