# РАСКЛАДКА ФАЙЛА .flp — точные ID событий (из исходников pyflp)

Получено из `pyflp/mixer.py`, `pyflp/arrangement.py`. Это ключ к переносу **всех**
громкостей, панорам, маршрутов и EQ без запуска FL.

## Микшер

`WORD=0x40, DWORD=0x80, TEXT=0xC0, DATA=0xD0`

| Событие | Формула | ID | Что |
|---|---|---|---|
| Name | TEXT+12 | **0xCC (204)** | имя дорожки (UTF-16LE) — прочитано верно |
| Routing | DATA+27 | **0xEB (235)** | маршруты: список байтов-флагов, по одному на дорожку-приёмник |
| Flags | DATA+28 | **0xEC (236)** | 12 байт: pad, u32 flags, pad (проверено: всюду 76) |
| Output | DWORD+19 | **0x93 (147)** | выходная дорожка |
| Input | DWORD+26 | **0x9A (154)** | входная дорожка |
| Color | DWORD+21 | **0x95 (149)** | цвет (RGBA) |
| Icon | WORD+31 | **0x5F (95)** | иконка |
| Params | DATA+17 | **0xE1 (225)** | громкость, панорама, EQ, посылы |

## Параметры микшера (0xE1) — записи по 12 байт

```
_u4   4 байта
id    1 байт   (см. таблицу ниже)
_u1   1 байт
ch    2 байта  u16
msg   4 байта  i32   ← само значение
```

Идентификаторы `id`:

| id | Параметр | Шкала |
|---|---|---|
| 0 | SlotEnabled | |
| 1 | SlotMix | |
| 64–191 | **уровни посылов** (64 + номер дорожки) | |
| **192** | **Volume** | 0…16000, 12800 = 0.0 дБ |
| **193** | **Pan** | −6400…+6400, 0 = центр |
| 194 | StereoSeparation | |
| 208/209/210 | Low/Mid/High Gain | |
| 216/217/218 | Low/Mid/High Freq | |
| 224/225/226 | Low/Mid/High Q | |

**Нерешённое:** в `vers1.flp` событие `0xE1` содержит **1025 записей**, но поле,
указывающее номер дорожки, ещё не определено: `_u4` = 0 у всех, `ch` даёт значения
до 60745. Значит либо у `0xE1` есть заголовок, либо номер дорожки кодируется иначе.
Разбирать дальше с этой точки: сравнить два проекта с заведомо разными громкостями.

### РАЗОБРАНО (проверено на дампе)

Реальная раскладка 12-байтовой записи `0xE1` в FL 25 оказалась не такой, как в pyflp:

```
[0..3]  u32  всегда 0
[4]     u8   идентификатор параметра (0, 1, …)
[5]     u8   всегда 0x1F (31)
[6]     u8   ← НОМЕР ДОРОЖКИ (0, 1, 2, 3 …)
[7]     u8   всегда 0x70 (112)
[8..11] i32  значение
```

Подтверждение на первых записях:

| hex | [4] | [6] дорожка | значение |
|---|---|---|---|
| `000000000000004000320000` | 0 | 0 | 12800 |
| `00000000001f007001000000` | 0 | 0 | 1 |
| `00000000011f007000320000` | 1 | 0 | **12800** |
| `00000000001f017000000000` | 0 | **1** | 0 |
| `00000000011f017000320000` | 1 | **1** | **12800** |
| `00000000001f027001000000` | 0 | **2** | 1 |

`12800` — это ровно **0.0 дБ по шкале громкости FL** (default). Номер дорожки идёт
подряд 0, 1, 2, 3 — значит байт `[6]` и есть индекс инсерта.

**Осталось сопоставить:** какой `id` в байте `[4]` соответствует громкости (192 в pyflp
не встречается — значит в FL 25 нумерация сдвинута или запись — часть блока параметров
с внешним id). Проверять так: взять дорожку с заведомо изменённой громкостью и найти
запись, где значение ≠ 12800.

### Проверка на реальных данных (vers1.flp)

- В файле встречаются id: **0, 1, 192, 193, 194, 208, 209, 210, 216, 217, 218, 224, 225, 226**.
- **id = 1 → Volume**: 12800 у всех дорожек 0–31 = **0.0 дБ у всех фейдеров**.
- **id = 0 → SlotEnabled**: 1 у всех.

### РАСКЛАДКА ПОДТВЕРЖДЕНА (дамп записей с id 192–226)

```
[0..3]  u32 = 0
[4]     0xC0/0xC1/0xC2/0xD0/0xD8/0xE0  = id (192 Pan? нет — см. ниже)
[5]     0x1F = 31  (константа)
[6]     НОМЕР ДОРОЖКИ — доходит до 500 (в FL столько инсертов!)
[7]     0x70 = 112 (константа)
[8..11] значение
```

Примеры:
```
00000000 c0 1f 00 70 cf310000  → id 192, дор. 0,  значение 12751
00000000 c1 1f 00 70 00000000  → id 193, дор. 0,  значение 0
00000000 c0 1f 40 70 00220000  → id 192, дор. 64, значение 8704
00000000 d0 1f 40 70 00000000  → id 208, дор. 64, значение 0
```

**ГЛАВНЫЙ ВЫВОД ПО ПРОЕКТУ:** в `vers1.flp` громкости ≈ 0.0 дБ, панорамы = 0 (центр),
стереоразделение = 0. То есть **фейдеры и панорамы микшера в сведении не участвуют** —
ширина и разведение гитар сделаны плагинами (Fruity Balance, Stereo Enhancer и т.п.)
и самим стереосодержимым файлов. Поэтому правки громкости/панорамы дорожек не давали
слышимого результата.

**Ошибка, которую надо не повторять:** фильтровать дорожки по `< 32` нельзя — номер
дорожки доходит до 500, и всё, что выше 31, отбрасывалось (из-за этого панорама
«не читалась»).

## Плагины

| Событие | ID | Что |
|---|---|---|
| PluginID.Data | **0xD5 (213)** | состояние плагина (для VST — запись с полями 50…57) |
| PluginID.Name | 0xCB (203) | имя канала рэка |
| PluginID.Wrapper | 0xD4 (212) | u32 insert, u32 slot |
| PluginID.Internal | 0xC9 (201) | внутреннее имя плагина |

Запись VST внутри `0xD5`: `u32 type`, затем цепочка `u32 field_id | u64 size | size bytes`,
где 50 PluginInfo, 51 FourCC, 52 GUID, **53 State**, 54 Name, 55 PluginPath, 56 Vendor.

**State (поле 53) — это родное состояние плагина.** Именно оно содержит все настройки
Kontakt, SD3, Fortin. Перенос в REAPER теоретически возможен (REAPER тоже хранит чанк
плагина в base64), но обёртки разные, поэтому это отдельная задача с проверкой на одном
плагине, а не «просто скопировать».

## Плейлист

`0xDA` проверен и **отвергнут** (710 событий по 68 байт, 1420 записей, все поля одинаковы).
Настоящий плейлист ещё не найден. По pyflp `PlaylistEvent` — это `ListEventBase` с 32-байтовыми
записями, но его ID в этой версии FL отличается от 0xDA.

## ПОПРАВКИ (см. `FLP-AUTOMATION.md`)

* `0xDA` — это **не** отвергнутый плейлист, а `ChannelID.EnvelopeLFO`: 710 = 5 огибающих × 142 канала,
  запись 68 байт. Плейлист — **`0xE9`** (233), 80-байтовые записи; в `vers1.flp` 779 клипов.
* Автоматизация — **`0xEA`**: заголовок 21 байт + `N` точек по 24 байта + 112 байт константного
  трейлера, `len == 133 + 24*N`. Точка: `f64 dx` (приращение в тиках), `f64 value` (0…1),
  `f32 tension`, `u32 flags`.
* Привязка к цели: имя канала `"<цель> - <параметр>"` + `0xDB` (Min/Max) + индекс канала;
  таблица линков — `0xE3`. Подробности и инструмент — в `FLP-AUTOMATION.md`.
