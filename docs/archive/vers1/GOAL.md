# ЦЕЛЬ: система понимания микса и сведения по референсам

## Формулировка цели

Построить и применять систему, которая **по аудио понимает микс так, как его слышит инженер**, и с её помощью свести трек к уровню референсов. Система должна:

1. определять, **какие инструменты играют** и в каких секциях;
2. измерять по каждому инструменту: **громкость, панораму, тембр, динамику, ширину**;
3. объяснять **почему что-то не слышно** (маскировка), а не просто «тихо»;
4. находить **«дешёвое» звучание** (резонансы, алиасинг, повторяемость сэмплов);
5. **сравнивать с референсами** по каждому инструменту после выравнивания общего уровня;
6. выдавать **план правок с числами** и подтверждать результат повторным замером;
7. работать **непрерывно по всему треку** и держать полный контекст.

---

## 7. Непрерывный анализ всего трека (обязательное требование)

Анализ **не по фрагментам**: весь трек от начала до конца, без пропусков.

**Требования:**
1. **Полное покрытие.** Каждая секунда трека проанализирована; нет «мы смотрели 45 секунд из шести минут».
2. **Скользящее окно с перекрытием** (окно 2–5 с, шаг ≤ 50 % окна) — чтобы ловить переходы, а не усреднять их.
3. **Непрерывность контекста.** Инструмент, опознанный в начале, остаётся тем же инструментом в конце: идентичность ведётся по всей длине, а не заново в каждом окне.
4. **Границы секций** определяются автоматически (энергия / самоподобие / смена плотности) и проверяются на слух по метрикам: смена состава, скачок громкости, изменение ширины.
5. **Накопительная статистика** по секциям и по треку: медиана, разброс, худшие моменты (а не только среднее).
6. **Поиск локальных провалов**: где именно инструмент пропадает (например, «женский вокал тише в хоре») — с указанием времени.
7. **Сравнение с референсом** тоже непрерывное: форма кривых по всей длине, а не один срез.
8. **Производительность:** полный трек 6 минут — Demucs на CPU ≈ 25–40 минут; допустимо, но запускать в фоне. GPU (V100) сокращает до секунд.

**Критерий приёмки п.7:** по любому моменту трека система может ответить: какой инструмент звучит, насколько громко, где панорамирован, кто его маскирует — и показать, как это менялось за последние секунды и в среднем по секции.

## Режимы анализа (обязательны все)

| Режим | Вход | Что даёт | Ограничение |
|---|---|---|---|
| По сумме | master-файл | тон, уровень, пик, корреляция, развитие | нет атрибуции — помечать выводы |
| По стемам | Demucs 4 стема | инструменты по группам, сравнение с реф-стемами | «other» = гитары+клавиши |
| По дорожкам | split-рендер DAW | точная атрибуция по инсертам | нужен split-рендер |
| По секциям | сегментация | баланс в куплете/хоре/бридже | нужна разметка |
| Во времени | окна 1 с | входы, провалы, плотность | разная структура песен |

**Правило:** каждый существенный вывод подтверждается минимум в **двух режимах**. При расхождении — сообщить о расхождении, не выбирать удобный.

## Что измерять (по каждому инструменту)

- тип (нейросеть: AudioSet-классы / эмбеддинги) + уверенность;
- громкость: RMS, LUFS (EBU R128);
- панорама: баланс L/R в дБ, side/mid в %;
- тембр: спектральный центр (Гц), наклон (дБ/окт), 10 октавных полос;
- динамика: crest, плотность транзиентов;
- артефакты: резонансы 2–5 кГц, алиасинг >15 кГц, корреляция соседних ударов.

## Что измерять (по миксу)

- матрица маскировки: кто кого перекрывает и на сколько дБ, по полосам;
- баланс: громкость каждого относительно громчайшего;
- стерео: корреляция общая и по полосам;
- уровень: true peak, LUFS, запас до клиппинга;
- дельты к референсу по каждому инструменту.

---

## Обязательные технические правила

1. **Атрибуция обязательна.** Запрещено «мало низа». Требуется: «бас на 6 дБ громче бочки в 40–100 Гц».
2. **Различать причины:** тихо / перекрыто / нет сигнала / не тот тембр.
3. **Проверка рендера:** перед анализом сверять время и хэш файла — не анализировать старый рендер.
4. **До/после:** каждая правка фиксируется парой замеров.
5. **Не менять больше одного параметра за шаг**, чтобы видеть вклад.
6. **Массовые мьюты** для соло-тестов возвращать в ноль и проверять чтением.
7. **Никаких выводов по памяти** — только по свежему замеру.

---

## Критерии приёмки

Система считается работающей, если на тестовом треке:

1. определяет состав инструментов по секциям (по дорожкам, не по сумме);
2. объясняет «не слышно бочку» числом: маскировка басом в 40–100 Гц (эталон: 9 дБ);
3. находит «дешёвое» числом: корреляция соседних ударов (эталон: 0.96 = один сэмпл);
4. даёт дельты к трём референсам по каждому инструменту (громкость / центр / ширина);
5. по итогу сведения профиль микса попадает в целевые окна:

| Параметр | Цель |
|---|---|
| низ <120 Гц | 48–54 % |
| муть 200–500 Гц | ≤ 3 % |
| середина | 12–15 % |
| presence 2–5 кГц | 3.5–4.5 % |
| воздух 10–16 кГц | 0.8–1.5 % |
| корреляция | 0.45–0.55 |
| true peak | ≤ −1.0 dBTP |
| громкость барабанов к басу | −3…−5 дБ (как в GRIMA) |

6. повторный замер после правок **подтверждает** сдвиг; если не подтверждает — правка считается невыполненной.

## Инструменты (уже реализованы)

`mix_map.py` — карта дорожек (громкость, панорама, тембр, конфликты)
`mask_check.py` — маскировка по полосам
`cheap_check.py` — «дешёвое»: резонансы, алиасинг, пулемёт
`stem_portrait.py` — тембр против референса
`mix_report.py` — полный отчёт + дельты к референсу
`timeline.py` — развитие во времени
`refcompare.py` — профиль микса против целей
`live_compare.py` — замер живого потока (нужен WASAPI shared)

## Чего не хватает

**Split-рендер дорожек из DAW** — один чекбокс `Split mixer tracks` в окне экспорта. Без него режим «по дорожкам» недоступен, и система работает только по сумме и стемам, то есть с ограниченной атрибуцией.

---

## Не-цели

- художественный вкус («нравится / не нравится»);
- оценка исполнения (фальшь, кривизна атаки);
- предсказание звучания на конкретных наушниках.
