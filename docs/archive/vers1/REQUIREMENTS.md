# ТРЕБОВАНИЯ: система понимания микса

Документ описывает, какой должна быть система, чтобы «слышать» микс так, как слышит инженер, и качественно сравнивать его с референсами. Написан как ТЗ: его можно отдать другому агенту или реализовать как пайплайн.

---

## 1. Проблема

Существующие замеры (доли полос, корреляция, presence) описывают **сумму**, а не то, что слышит человек. Из-за этого:
- нельзя сказать, какой инструмент где звучит и почему его не слышно;
- нельзя отличить «тихо» от «перекрыто другим инструментом»;
- нельзя сравнить тембр инструмента с тем же инструментом в референсе;
- нельзя понять развитие во времени (куплет/хор/бридж).

**Требуется система, которая по аудио строит полную картину микса и объясняет её словами.**

## 2. Входные данные (обязательно)

1. **Аудио каждой дорожки микса отдельно** — не сумма. Источник: рендер FL с включённым `Split mixer tracks` (по файлу на инсерт), либо N соло-рендеров.
2. **Сумма микса** (master) — для проверки баланса и клиппинга.
3. **3+ референса** в жанре, желательно с известной инструментовкой.
4. **Разметка секций** трека (куплет / хор / бридж) либо автоматическая сегментация.

Без п.1 система обязана явно сообщать: «анализ только по сумме, атрибуция инструментов недостоверна».

## 3. Что система обязана измерять

### 3.1 По каждой дорожке
- **тип инструмента** нейросетевой моделью (AudioSet-классы или эмбеддинги) с указанием уверенности;
- **громкость**: RMS и LUFS (EBU R128, интегрированная и short-term);
- **панорама**: баланс L/R в дБ, доля бокового сигнала (side/mid);
- **тембр**: спектральный центр, наклон дБ/окт, 10 октавных полос;
- **динамика**: crest factor, плотность транзиентов (ударов в секунду);
- **признаки «дешёвого»**: резонансные пики 2–5 кГц, алиасинг >15 кГц, повторяемость сэмплов (корреляция соседних транзиентов).

### 3.2 По миксу в целом
- **маскировка**: для каждой пары инструментов и каждой полосы — кто кого перекрывает и на сколько дБ;
- **баланс**: громкость каждого инструмента относительно самого громкого;
- **стерео**: корреляция L/R общая и по полосам;
- **уровень**: true peak, LUFS, запас до клиппинга;
- **развитие**: те же величины по секциям и по секундам.

### 3.3 Сравнение с референсом
Для каждого инструмента — **дельта к тому же инструменту в референсе**: громкость (дБ), центр (Гц), ширина (%), маскировка. Оценивать **после выравнивания общего уровня**, иначе разница уровня микса маскирует баланс.

## 4. Требования к качеству

1. **Атрибуция обязательна.** Любое утверждение о миксе должно указывать, к какому инструменту оно относится. «Мало низа» — запрещено; «бас на 6 дБ громче бочки в 40–100 Гц» — требуется.
2. **Все выводы воспроизводимы** повторным замером; фиксировать «до» и «после» каждой правки.
3. **Различать причины**: «тихо» (уровень), «перекрыто» (маскировка), «нет в источнике» (нет сигнала), «не тот тембр» (спектр).
4. **Никаких выводов по сумме**, если доступны дорожки.
5. **Проверка артефактов рендера**: сверять MD5/время файла, чтобы не анализировать старый рендер (уже случалось: три «версии» были одним файлом).

## 5. Выходные данные

Отчёт по каждому инструменту и по секциям:
- тип + уверенность;
- громкость и панорама;
- тембр и ширина;
- кто кого маскирует;
- дельта к референсу;
- **список конкретных правок с числами** (что, на сколько дБ, где).

## 6. Рекомендуемый современный стек

| Задача | Модель/инструмент |
|---|---|
| Разделение на инструменты | HTDemucs / `htdemucs_ft`, либо BS-RoFormer (SOTA) |
| Типы и категории | CLAP (аудио-текст) или PANNs CNN14 (AudioSet) |
| Тембровые эмбеддинги | MERT-v1 (музыка) / CLAP |
| Громкость | pyloudnorm (EBU R128) |
| Маскировка | поканальные спектры + порог 6 дБ |
| Секции | self-similarity / energy segmentation |
| Ускорение | GPU (V100) для Demucs/CLAP; на CPU 60 с ≈ 45 с обработки |

## 7. Критерии приёмки

Система считается решающей задачу, если на тестовом миксе она:
1. **определяет, какие инструменты играют** в каждой секции (по дорожкам, не по сумме);
2. **объясняет «не слышно»** через маскировку с числом в дБ (пример: бас громче бочки на 9 дБ в 40–100 Гц);
3. **находит «дешёвое»** числом (пример: корреляция соседних ударов 0.96 = один сэмпл);
4. **сравнивает с 3 референсами** и даёт дельты по каждому инструменту (громкость/центр/ширина);
5. **даёт план правок с числами**, а после применения — подтверждает изменение повторным замером;
6. **не врёт про рендер**: проверяет, что анализируемый файл действительно новый.

## 8. Явные не-цели

- художественный вкус («нравится / не нравится») — вне системы;
- оценка исполнения (фальшь, кривизна атаки) по аудио — требует отдельной модели;
- предсказание, как микс будет звучать на конкретных наушниках.

## 9. Минимальный пайплайн (одна команда)

```
1. split-рендер дорожек из DAW        → tracks/*.wav
2. LUFS + pan + спектр по каждой      → per-track метрики
3. классификация типов (PANNs/CLAP)   → тип + уверенность
4. матрица маскировки по полосам      → кто кого глушит, дБ
5. сегментация секций                 → метрики по секциям
6. сравнение с референсами            → дельты по инструментам
7. отчёт: тип, уровень, панорама, маскировка, дельта, план правок
```

Реализация на текущей машине: `mix_map.py`, `mask_check.py`, `cheap_check.py`, `stem_portrait.py`, `mix_report.py`, `timeline.py` — всё уже написано; не хватает только шага 1 (split-рендер).

## 10. Режимы анализа — обязательны ВСЕ

Система должна уметь работать в каждом режиме и явно указывать, в каком режиме получен вывод.

### 10.1 По сумме (master / микс целиком)
- что доступно: тональный баланс, громкость, пик, корреляция, «дешёвое», развитие по времени;
- чего нельзя: атрибуция инструментов;
- когда применять: быстрая проверка «тон/уровень/клиппинг», первичный скрининг.
- **Обязательное ограничение:** выводы по сумме помечать как «без атрибуции».

### 10.2 По стемам (Demucs: drums / bass / vocals / other)
- что доступно: громкость, панорама, тембр и маскировка по 4 группам; сравнение с референсными стемами;
- ограничение: «other» смешивает гитары/клавиши/эффекты;
- когда применять: когда нет split-рендера, но нужно понимать инструменты.

### 10.3 По дорожкам (split-рендер из DAW)
- что доступно: точная атрибуция по каждому инсерту — тип, уровень, панорама, маскировка, конфликты;
- когда применять: основной режим для сведения.

### 10.4 По секциям (куплет / хор / бридж / брейк)
- что доступно: как меняется баланс и плотность по ходу трека;
- обязательно для жалоб вида «в хоре женский вокал тихо» — это вопрос секции, а не среднего.

### 10.5 Во времени (по секундам)
- что доступно: развитие, входы инструментов, провалы, накопление плотности;
- сравнение формы кривых с референсом (с оговоркой о разной структуре).

### 10.6 Перекрёстная проверка (обязательна)
Любой существенный вывод должен подтверждаться **минимум в двух режимах**. Пример: «барабанов не слышно» → подтверждено по стемам (маскировка 9 дБ) и по дорожкам (уровень бочки против баса). Если режимы расходятся — сообщать о расхождении, а не выбирать удобный.

### 10.7 Единый формат вывода
Каждый отчёт обязан содержать: режим анализа, инструмент (если применим), величину, единицу, дельту к референсу, и вердикт. Без этого вывод не считается результатом.
