## 3. Раскладка события `0xEA` (главное)

Событие: `u8 0xEA` + varint длины + payload. Payload = **21 байт заголовка + N × 24 байта точек + 112 байт трейлера**.

```
payload_len == 133 + 24 * N          <-- проверено на всех 728 событиях (0 исключений)
```

### 3.1 Заголовок (21 байт)

| offset | тип | значение | поле |
|---|---|---|---|
| 0x00 | u32 | всегда `1` | версия/флаг блока |
| 0x04 | i32 | всегда `64` | lfo_amount |
| 0x08 | u8 | `0` (один раз `1`) | lfo_shape |
| 0x09 | u16 | всегда `4` | — |
| 0x0B | u16 | всегда `0` | — |
| 0x0D | u32 | всегда `3` | — |
| 0x11 | u32 | **N** | **количество точек** |

Все поля кроме `0x11` — константы во всех 728 событиях (проверено гистограммой), т.е. реальная
информация в заголовке — только число точек.

### 3.2 Точка (24 байта)

| offset | тип | поле |
|---|---|---|
| +0x00 | **f64** | `dx` — приращение по X **относительно предыдущей точки**, в тиках PPQ. У первой точки всегда `0.0` (728/728) → кривая начинается с тика 0 |
| +0x08 | **f64** | `value` — нормированное значение Y. Обычно 0…1, **может выходить за 1** (встречено 1.25 и 1.3333) |
| +0x10 | **f32** | `tension` — кривизна сегмента, знаковая (встречено −0.32…0.0; 0 = прямая) |
| +0x14 | u32 | флаги точки: `0x00000000` первая точка, `0x02000000` обычная/последняя, `0xFF000000` сегмент с кривизной (наблюдение, не доказано) |

Позиция точки считается накопительно: `tick[i] = tick[i-1] + dx[i]`, `tick[0] = 0`.
**X — это тики при PPQ проекта** (96 → 96 тиков = 1 четверть). 737 из 1507 позиций кратны 96,
остальные — микротайминг (встречаются доли тика: 63.5, 65.25, 71.417).

Вертикальный «ступенчатый» переход FL пишет как две точки с одинаковым X и разными value
(`dx = 0`) — это нормально и встречается в реальных кривых.

### 3.3 Трейлер (112 байт)

Последние 112 байт payload — **побайтово идентичны во всех 728 событиях** из 180 проектов.
Значит никакой информации о конкретном клипе они не несут (это дефолтное состояние канала).
Содержимое (смещения от начала трейлера):

```
+0    u32 = 1
+4    0xFF x 16
+20   u32 = 128      +24 u32 = 128      +28 u32 = 0      +32 u32 = 128
+36   u32 = 5        <-- ChannelType.Automation
+40   u32 = 3        +44 u32 = 1        +48..+55 = 0
+56   f64 = 1.0
+64..+71 = 0         +72 u32 = 1        +76 u32 = 0
+80   0xFF x 12
+92   u32 = 45819 (0xB2FB)
+96..+111 = 0
```

### 3.4 Пример (канал 8, `Tempo`, 181 байт)

```
01 00 00 00 40 00 00 00 00 04 00 00 00 03 00 00 00 02 00 00 00   заголовок: 1, 64, 4, 3, N=2
00 00 00 00 00 00 00 00 | 00 00 00 80 77 77 e9 3f | 00 00 00 00 | 00 00 00 00
     dx = 0.0                value = 0.795833           tension      flags
00 00 00 00 00 68 85 40 | 00 00 00 80 77 77 e9 3f | 00 00 00 00 | 00 00 00 02

01 00 00 00 ff ff ... (112 байт константного трейлера)
```

## 4. Как это проверено (без запуска FL)

1. **Уравнение размера.** 728 событий 0xEA в 180 проектах: `len == 133 + 24*N` выполняется всегда,
   трейлер всегда ровно 112 байт (гистограмма: `{112: 728}`).
2. **Монотонность.** 0 нарушений: `tick[i] >= tick[i-1]` на всех 1507 точках, `dx[0] == 0` всегда.
3. **Правдоподобие значений.** `value` в 0…1.333, `tension` в −0.32…0, число точек 2…10.
4. **Независимая сверка с `pyflp`** (`pyflp.channels.automations`, тот же файл): 60 проектов,
   248 клипов, 519 точек — **0 расхождений** по позиции, значению и tension.
   `pyflp` подтверждает и смысл полей (`AutomationEvent.STRUCT`: `_u1` 4B, `lfo.amount` i32, …,
   `points` — PrefixedArray с 24-байтовыми записями), но **не** даёт привязку к цели и размещение.
5. **Осмысленность на реальных кривых.** `мда.flp`, канал 52 (`Insert 6 - Volume`): 10 точек,
   значения 0.6273 → 0.4833 → 0.5648 → 0.4667 → 0.6273, два ступенчатых перехода (`dx=0`),
   длина 194.99 тика. Это читаемая кривая «просадка → возврат», а не шум.
6. **Размещение.** `0xE9` (Playlist, 80-байтовые записи, `pattern_base == 20480` у всех 779 клипов —
   самопроверка формата) показывает, что 4 клипа vers1 стоят в плейлисте 6 раз на дорожке 1.

## 5. Привязка к цели

Отдельного «указателя на параметр» в `0xEA` **нет**. Цель восстанавливается из трёх согласованных
источников — все три использует инструмент:

**(а) Индекс канала.** Автоматизация — это канал рэка (`0x15 = 5` = `ChannelType.Automation`),
его номер = порядок блока в потоке (0…141 в `vers1.flp`). Он же повторяется в `0xE3` (см. ниже) —
совпадение 4/4 в `vers1.flp` и 8/8 в `мда.flp`.

**(б) Имя канала.** FL сам пишет `"<цель> - <параметр>"`, когда клип создаётся с параметра:

| имя в файле | цель | параметр |
|---|---|---|
| `Insert 5 - Volume` | инсерт 5 | Volume |
| `Insert 6 - Volume` | инсерт 6 | Volume |
| `Fruity Parametric EQ 2 (Insert 3) - Mute / solo` | плагин в инсерте 3 | Mute/solo |
| `Sound_6042 - Channel pitch` | канал Sound_6042 | питч канала |
| `Tempo`, `Tempo #2` | проект | Tempo |

**(в) Событие `0xDB` (Levels) — Min/Max параметра.** У автоматизаций первые два i32 — это не pan/volume,
а **диапазон** управляемого параметра в его родных целых единицах:

| Min..Max | параметр | смысл |
|---|---|---|
| `0 .. 12800` | Volume | 12800 = 0.0 дБ (шкала микшера FL), линейно по value |
| `1250 .. 4250` | Tempo | родные единицы, **нелинейно** по value |
| `5600 .. 7200` | Channel pitch | центы, 6400 = 0 |
| `0 .. 12800` | Mute / solo | переключатель: 0 = выкл, 12800 = вкл |

Значение параметра: `value_param = min + value * (max - min)`.
Для Volume это точно (12800 = 0.0 дБ). Для Tempo — **нет**: два проекта с разными темпами дают взаимно противоречивые линейные
отображения (155.5 BPM при value 0.7958 и 210 BPM при 0.6273), поэтому
шкалу темпа я не утверждаю; в инструменте такие значения помечены как «indicative».

### `0xE3` — таблица линков (20 байт), расшифрована частично

```
u16  = 0
u16  = ИНДЕКС КАНАЛА автоматизации     <-- совпадает с порядком блока
u32  = 0
u32  = "target word"                   <-- младшие 2 байта: 0x1FC0 = Volume, 0x0005 = Tempo
u32  = 8
u32  = 0x1D5 (константа)
```

`target word` раскодирован не до конца: в `мда.flp` это `0x21001FC0`, `0x21401FC0`, `0x21801FC0`,
`0x22001FC0`, `0x40000005`; в `вертушечная1` — `0x75001FC0`. Младшие 16 бит стабильно кодируют
семейство параметра (Volume / Tempo), старшие — что-то вроде адреса слота/инсерта.
**Для чтения автоматизаций это не нужно**: имя клипа даёт цель точнее.

Важно: **индекс параметра плагина в открытом виде не хранится** — только человекочитаемое имя
(`Fruity Parametric EQ 2 (Insert 3) - Mute / solo`). Чтобы узнать конкретный № параметра, нужно
сопоставить имя с `fl_plugin_get_params` уже в запущенном FL.

## 7. Другие механизмы автоматизации (не 0xEA)

* **`0xDF` — pattern-контроллеры** (`PatternID.Controllers`, 12-байтовые записи:
  `pos u32, u8, u8, channel u8, flags u8, value f32`). Это автоматизация, записанная **в паттерн**
  (движение ручки при включённой записи), а не клипом. В `vers1.flp` — 1 запись (позиция 576,
  канал 4, value 0.0), то есть пустышка. В `говно/untitled 1.flp` — 14 записей. Инструмент считает
  их в `summary`, но точки не разворачивает: `pos` может быть как абсолютным, так и дельтой.
* **`0xDA` — EnvelopeLFO** (68 байт): настройки огибающих/LFO канала (attack/decay/sustain,
  LFO speed/shape). Это **не** нарисованные кривые автоматизации, а параметры модуляции.
  Не путать с автоматизацией; в `FLP-SPEC.md` этот id был ошибочно приписан плейлисту.

## 8. Ограничения

1. Парсер `flp_events.py` настроен на FL 25. Из 183 проверенных файлов **2 не разбираются**
   (старый формат: падение на `0xC4`/`0xD4` с «overruns chunk»). Инструмент в этом случае падает
   с ошибкой парсера, а не с неверными данными.
2. Шкала Tempo не расшифрована (нелинейна) — значения выводятся нормированными.
3. `target word` в `0xE3` раскодирован только на уровне семейства параметра.
4. Индекс параметра плагина доступен лишь через имя, не числом.
5. Плейлист читается только для 80-байтовых записей (FL 24.2+); для старых проектов размещение
   показывается как «нет данных» → `items = 0`.
