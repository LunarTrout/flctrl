# Перцептивный анализ микса: что нашлось и что с этим делать

Дата: 2026-11-02. Всё, что ниже, проверено запуском на этом компьютере (Windows 11, CPU, Python 3.13 через uv),
кроме мест, где явно написано «не проверял».

---

## 0. Короткий вывод

Ключевой апгрейд — не ещё одна «полоса», а **удельная громкость N'(z)** по шкале Барка:
она уже учитывает сжатие слуха, маскировку и неравномерность чувствительности.
Считать её по кадрам дёшево (0.25 мс на кадр), поэтому один и тот же движок даёт
анализ в точке, по секции, по такту, по всей длине и по стемам.

Готовая библиотека, которая это делает на Windows без сборки: **phonometry** (MIT, 131★).
Проверено: `pip`-wheel `py3-none-any`, Python >= 3.13, все метрики считаются.

## 1. Проверено на нашем материале (реальные цифры)

`tools-local/perceptual.py` — новый инструмент (описание в конце).
Все файлы приводятся к −14 LUFS и слушаются на 90 dB SPL, иначе модель Zwicker'а
сравнивает разные уровни прослушивания и цифры несопоставимы.

### Наш микс против GRIMA (первые 90 с, одинаковый уровень)

| | наш `full_mix.wav` | GRIMA | дельта |
|---|---|---|---|
| громкость N, сон | 75.4 | 75.7 | −0.4 % |
| уровень, фон | 102.3 | 102.4 | −0.1 |
| **резкость DIN, acum** | **1.80** | **1.50** | **+0.30 (+20 %)** |
| слышимый баланс sub/bass/lowmid | 11 / 14 / 15 % | 10 / 16 / 19 % | низ ослаблен |
| mid/upmid | 19 / 21 % | 21 / 21 % | ≈ |
| **presence / air** | **13 / 7 %** | **10 / 4 %** | **+3 / +3 п.п.** |
| корреляция L/R | 0.77 | 0.41 | микс уже референса |
| side/mid, дБ | −8.8 | −3.8 | |
| потеря в моно, дБ | −0.54 | −1.52 | |

Читается так: микс громкий не хуже, но **заметно резче** (acum +20 %), с перевесом
presence/air и недобором низкой середины. Это машинная формулировка того же, что
«вокал ярче на +1934 Гц» и «гитары шире» — но в одной шкале, по которой можно ставить цель.

Важно: **«шире» относится к гитарам, а не к миксу**. По корреляции микс уже референса
(0.77 против 0.41), т.е. центр плотнее, а ширина гитар не вытягивает общую картину.
Это стоит перепроверить прежде, чем крутить ширину.

### По секциям (200 с, карта по новизне перцептивного профиля)

```
0–35    N 81.9  phon 103.6  резк 1.99   (самая громкая и самая резкая)
35–74   N 69.9  phon 101.2  резк 1.65   (спад, −12 сон)
74–84   N 74.4  phon 102.1  резк 1.74
84–137  N 75.8  phon 102.4  резк 1.70
137–186 N 79.2  phon 103.0  резк 1.70
186–200 N 74.6  phon 102.1  резк 1.80
```
Разброс между секциями 12 сон — это и есть «динамика», которую не видно в LUFS.

### Маскировка по стемам (my60, 0–60 с, N'(z) на одной калибровке)

| стем | доля N' | sub | bass | lowmid | mid | upmid | pres | air |
|---|---|---|---|---|---|---|---|---|
| other (гитары/баян/цимбалы) | **54.6 %** | 29 | 45 | 55 | **64** | **70** | 62 | 39 |
| vocals | 20.3 % | 7 | 20 | 32 | 27 | 16 | 14 | 27 |
| drums | 12.8 % | 18 | 9 | 6 | 7 | 12 | 21 | 33 |
| bass | 12.3 % | **47** | **26** | 7 | 2 | 2 | 2 | 1 |

Вывод: середину и верхнюю середину занимает `other` (гитарная стена) — 64–70 %.
Барабаны в lowmid/mid — 6–7 %, это и есть «барабаны тихие» на языке восприятия.
Бас громкий **только в своих полосах** (47 % sub, 26 % bass), но в общей громкости — 12 %:
именно поэтому «энергия» и «слух» дают разные ответы про бас.

Оговорка: Σ N' стемов / N' микса = 1.55. Demucs-стемы не складываются в микс идеально,
поэтому **доли** стемов валидны, а абсолютная сумма — нет.

### Разборчивость вокала (STOI: вокал-стем как «чистый», микс как «испорченный»)

Окно 15 с с максимальной энергией вокала у каждого трека:

| трек | STOI |
|---|---|
| наш микс | **0.677** |
| Wintersun | 0.655 |
| GRIMA | 0.557 |

Наш вокал **не забит** — он разборчивее обоих референсов. Это согласуется с перевесом
presence: вокал скорее слишком вперёд/ярко, чем теряется. Полезный контр-аргумент
к «надо поднять вокал».

- Zwicker по готовым 28 полосам — **0.25 мс на кадр** (наш движок: весь трек 352 с — **6.4 с**, 55× реального времени);
- ECMA-418-2 loudness — 100 с (0.27×);
- **ECMA-418-2 roughness — 21 с (1.3× реального времени, годится на весь трек)**;
- ECMA-418-2 tonality — 194 с (0.14×, только на секции/события);
- ISO 532-3 (Moore-Glasberg TVL, бинаурально) — 81 с на 10 с (0.12×, только точки/секции).

| Что | Где | Ограничения |
|---|---|---|

## 3. Архитектура, которая даёт гибкость

```
WAV/стем
  └─ 28 третьоктавных полос по кадрам (50 мс, Hann, IEC 61260)   ← numpy, 0.1 мс/кадр
       └─ loudness_zwicker_from_spectrum()                       ← 0.25 мс/кадр
            ├─ N(t) соны, phon(t), N5/N10
            ├─ N'(z,t) 240 полос Барка  ← маскировка, доли стемов, секционные отпечатки
            └─ sharpness_din_from_specific()                     ← 0.01 мс/кадр
```
Всё остальное — агрегация одного и того же массива:
- **точка** — окно ±2 с вокруг `--at`;
- **секция** — срез `--section 95:140` или авто-карта по новизне;
- **такт** — если есть сетка битов (librosa/allin1), границы кадров по битам;
- **весь трек** — `--grid out.npz` (t, lv, N, phon, sharp, specific);
- **инструмент** — тот же расчёт по стему на общей калибровке, доли N'.

Ключевая деталь: **калибровка**. Модель Zwicker'а нелинейна по уровню. Если сравнивать
файлы на разной громкости, получите ложные различия. Поэтому: нормализация в −14 LUFS,
затем общий сдвиг в 90 dB SPL. В `perceptual.py` это `--lufs` + `calibrate()`.

Проверка точности движка: тот же файл, посчитанный официальным стационарным путём
`loudness_zwicker(stationary=True)` — 76.4 сон / 102.6 фон; через мои 28 полос —
74.2 сон / 102.1 фон. Расхождение 3 % по громкости и 0.5 фон, при ускорении в тысячи раз.

## 4. План: что прогнать на нашем треке и референсах

1. **Поставить окружение** (одна команда, ничего не собирается):
   ```
   uv run --no-project --python 3.13 --with phonometry --with soundfile --with numpy \
     --with scipy --with pyloudnorm python tools-local/perceptual.py ...
   ```
2. **Снять перцептивный профиль** с микса и 6 референсов на одинаковых по типу секциях
   (`--section`), а не целиком. Смотреть три числа: N, резкость acum, N'(z) по 7 областям.
3. **Сопоставить секции** по N'(z) (косинус/евклид на 24 полосах Барка) — это заменит
   энергетический `secmatch2` на перцептивный. Припев к припеву, бласт к бласту.
4. **Маскировка по стемам** на тех же секциях: доля N' каждого стема по областям.
   Цель — не «other 55 %», а «other 70 % в upmid» → отсюда конкретный EQ/панорама.
5. **Roughness** на 2–4-секундных окнах вокруг тарелок/баяна/скрима: покажет «грязь»
   и «жёсткость», которые не видны в спектре. (1.3× реального времени — можно весь трек.)
6. **Tonality** — только на подозрительных секциях (0.14×), искать тональные резонансы
   (баян, цимбалы, резонанс бочки).
7. **STOI по вокалу** на одинаковых окнах у себя и референсов — индекс выживаемости вокала.
   Уже есть базовые значения: 0.677 / 0.655 / 0.557.
8. **Дельта АЧХ** через matchering на паре однотипных секций — получить кривую, которую
   «хочет» референс, и сверить с дельтой N'. Если совпадают — можно двигать EQ.
9. **Проверка гипотезы** через pedalboard (Windows-wheels до cp315, хостит VST3):
   отрендерить вариант с Pro-Q 4 и сравнить N'/резкость до/после, не трогая проект.
10. **Живой режим**: тот же расчёт на ring-buffer из loopback (уже есть `live_meter.py`)
    → показывать N и N'(z) в реальном времени, а не 8 полос энергии.

## 5. Грабли

- **Не сравнивать абсолютные фоны на разной громкости** — модель нелинейна. Только equal-loudness.
- **PEAQ и STI не для микса**: первый — про кодеки, второй требует тестового сигнала.
- **Demucs-стемы не складываются в микс** (Σ N' = 1.55× у нас): доли валидны, сумма — нет.
- **essentia/madmom/allin1** на Windows — сборка/блокеры; не тратить время, есть замена.
- **Python 3.12**: phonometry требует >=3.13 (у неё нет 3.12-wheel). Это не блокер: инструмент
  запускается отдельным окружением через `uv run --python 3.13`, основной стек (demucs/librosa)
  трогать не нужно. Если принципиально нужен 3.12 — берите MoSQITo (работает с 3.5+), но
  потеряете ECMA-418-2 и N'(z) в удобном виде.
- **Voxengo SPAN, Tonal Balance, true:balance** — энергетические, не перцептивные:
  они переоценивают низ (энергия), тогда как слух даёт низу мало громкости.
  Отсюда классическая ошибка «бас громкий по SPAN, а по слуху — нет».
- **Один трек ≠ один трек**: сравнивать надо секции одного типа, иначе дельта отражает
  разницу аранжировки, а не микса.
