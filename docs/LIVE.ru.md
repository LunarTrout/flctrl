# Живой захват: откуда берётся поканальный звук

Задача: в FL Studio нет API, который вернул бы звук дорожки микшера. Метры дают огибающие,
песня рендерится одним файлом, а стемы требуют ручной галочки в экспорте.

Решение использует единственное место, где FL сама отдаёт PCM по дорожкам: **Disk
Recording**. Каждая взведённая дорожка пишет свой WAV. Если перехватить или прочитать этот
поток — получаешь звук дорожки: после её обработки, до мастера.

---

## 1. Что даёт сама FL

- Взвод дорожки: `mixer.armTrack(index)` (переключает), `mixer.isTrackArmed(index)`.
- Запись: `transport.record()` переключает; `transport.isRecording()` читает.
- Воспроизведение: `transport.start()`, `transport.setSongPos(position)`, `transport.stop()`.
- Файлы записи попадают в `…/Documents/Image-Line/FL Studio/Audio/Recorded`.
- При первом нажатии Record всплывает модальное окно **Recording**, если его не погасить:
  `HKCU\Software\Image-Line\FL Studio 25\DSTITF\PopupRec = 1` отключает его
  (`live.suppress_popup`).

Два факта, которые стоили времени:

1. **Song mode обязателен.** В pattern mode FL играет выбранный паттерн, а не песню, и
   снимок выходит пустым.
2. **Запись реального времени.** Две секунды музыки — две секунды захвата; более быстрого
   пути для живого снимка нет (офлайн-рендер — другой механизм).

---

## 2. Режим `files` (по умолчанию)

```
точка сохранения  →  Ctrl+S + копия .flp
взвод             →  mixer.armTrack для нужных дорожек
запись вкл        →  transport.record()
играть            →  setSongPos(start); start()
ждать             →  seconds
стоп              →  stop(); запись выкл
чтение            →  новые файлы в Recorded → soundfile → лента
очистка           →  удалить эти файлы
восстановление    →  снять взвод; вернуть song/pattern
```

Свойства:

- диск трогается только на время снимка, потом пуст;
- FL не перезапускается, проект не перезагружается;
- взвод и режим восстанавливаются даже при исключениях (`try/finally`);
- проверено: 29 дорожек за один снимок, `Recorded` после — пуста.

Оговорка: в song mode FL может вставить в плейлист аудиоклип записи («auto-create audio
clip»). Это так и не было подтверждено как причина жалобы на громкость, но именно поэтому
библиотека не гоняет снимки на рабочем проекте без спроса.

## 3. Режим `memory` (без диска)

FL пишет PCM через `WriteFile` из `FLEngine_x64.dll+0x3b5fa`. Полезная нагрузка — сырой
float32 стерео; первая запись файла несёт 4-байтный префикс, остальные — непрерывный PCM.
Мы сверили буфер с полезной нагрузкой получившегося WAV побайтово: 59 392 байта совпали
точно.

Хук:

- `CreateFileW` → запоминает хэндлы, чей путь совпадает с `Recorded/*.wav`;
- `WriteFile` → для этих хэндлов копирует буфер в список и обнуляет длину записи: FL
  считает, что записала, а на диск уходит только 76-байтный заголовок.

Выгрузка Frida-скрипта, пока поток записи FL находится внутри хука, может уронить FL,
поэтому хук живёт в **отдельном долгоживущем демоне** (`tools-local/hook_daemon.py`,
`127.0.0.1:9788`):

- один attach на сессию FL;
- команды `ping`, `start`, `stop`, `quit` по сокету с длиной сообщения в префиксе;
- аудио передаётся сжатым (`zlib` + base64), потому что 29 дорожек сырым JSON не
  укладывались в таймаут;
- `ensure_daemon()` поднимает его по требованию и перецепляется, если PID FL изменился.

Режим пишет только заголовки, их убирает `live.clean()`. На FL 25.2.5 он был менее
стабилен, чем `files`, поэтому включается явно.

## 4. Безопасность

**Точки сохранения.** Перед каждым снимком: Ctrl+S в FL (окно поднимается в фокус; если
поднять не удалось — сохранение отменяется, вместо того чтобы печатать в чужое окно), затем
копия `.flp` в `~/Backups/flctrl/`. Одинаковые состояния пропускаются по SHA-1, старые
точки подрезаются (20 по умолчанию). Если сохранить не удалось, копируется свежий автосейв
FL, и в результате стоит `origin: "autosave"`.

**Восстановление состояния.** Снимок запоминает прежний режим и набор взведённых дорожек и
возвращает оба в `finally`, в том числе если мост отвалился посреди захвата.

**Ограниченные ожидания.** Никаких `sleep`-циклов по неизвестному условию: игра ограничена
по времени, появление файлов проверяется один раз, у вызовов моста есть таймауты.

---

## 5. Отказы, встреченные на практике

| Симптом | Причина | Лечение |
|---|---|---|
| Снимок пустой | pattern mode, либо `start` вне аранжировки | song mode; проверить `start` |
| FL встаёт на модальном окне | `PopupRec = 0` | `live.suppress_popup(True)` (автоматически) |
| Демон не поднимается | старый демон висит на мёртвом PID | `ensure_daemon()` гасит его и цепляется заново |
| FL исчезает во время снимка | выгрузка хука, пока поток записи внутри него | режим `files` либо не отцеплять демон |
| Файлы остаются в `Recorded` | процесс убили посреди снимка | `live.clean()` убирает заголовки |

---

## 6. Что проверено, а что нет

Проверено на FL 25.2.5 (build 5319):

- 29 дорожек за один снимок, по WAV на дорожку, имена совпадают;
- снятые дорожки — не копии мастера (попарная корреляция: GTR L1 ↔ GTR R1 0.046;
  максимум 0.614 у DRUM BUS ↔ DRUMS SD3);
- `Recorded` пуста после снимка; FL жива; проект не изменён, кроме восстановленного взвода;
- точки сохранения создаются реальным Ctrl+S (`origin: "save"`), дедуп по SHA-1;
- режим `memory`: файл остаётся 76 байт, при этом снято 712 784 байта PCM.

Не проверено:

- поведение опции «auto-create audio clip» во время снимка (см. оговорку выше);
- длинные снимки (> 30 с) — дальше нескольких секунд не тестировалось;
- другие версии FL, кроме 25.2.5.
