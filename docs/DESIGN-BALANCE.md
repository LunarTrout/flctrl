# Баланс инструментов: что известно и что делаем

Документ фиксирует **решения**, принятые по литературе, а не по интуиции.
Каждое решение — с источником и с тем, как его проверить.

## 1. Что доказано в литературе

**Две директивы сведения (Deruty, Pachet, Roy, JAES 62(10), 2014).**
На 55 рок-мультитреках: при хороших условиях прослушивания микшеры подгоняют
**типичный спектральный профиль** жанра; при плохих — максимизируют
**слышимость каждого трека**. Громкость трека линейно связана с его
спектральным центроидом (яркостью).
Вывод для нас: баланс нельзя описывать одной осью. Нужны две — профиль микса
(форма) и слышимость трека (разборчивость).

**Маскировка между стемами структурна (Cofer, Belmont University, 2019).**
30 песен рок-жанра, кросс-аналитическая модель громкости, пять полос:
гитары — **наименее маскируемый** стем во всех полосах, затем вокал, бас,
барабаны; тесная связь гитары↔вокал, барабаны↔бас — слабее.
Вывод: отношения «кто кого маскирует» — свойство жанра, а не трека; их можно
измерить на корпусе и использовать как цель.

**Двухступенчатое сведение лучше одноступенчатого (Shi et al., ISMIR 2026).**
Три слушательских эксперимента: разделение на внутригрупповую обработку и
межгрупповую координацию значимо улучшает результат; неверная группировка
заметно портит итог, а ошибки громкости переносятся слабее. Для внутригруппового
баланса используется **ELL — equal local loudness**, обучение не требуется.
Вывод: сначала баланс внутри подгрупп, потом между подгруппами. Это же делает
подход переносимым: группировка задаётся ролями, а не именами дорожек.

**Частичная громкость как мера слышимости (Ma, Reiss, Black, AES 53rd, 2014;
PEASS — Emiya, Vincent, Harlander, Hohmann, 2011).**
Слышимость источника в миксе считается через приращение громкости:
`N_partial = N(микс) − N(микс без источника)`, а PEASS строит на этом же
четыре компонента (OPS/IPS/APS/TPS) через гамматон-фильтры и разложение
искажений по кадрам.
Вывод: наша `flctrl/partial.py` идёт по проверенному пути; альтернатива —
портировать PEASS, но он про оценку разделения, а не про сведение.

**Типоспецифичные цели переносимы (Martinez et al., 2022, FxNorm).**
Стемы нормализуются по средней громкости **своего типа**, модель учится
отклонению от неё; это позволило обучить автоматическое сведение на
«мокрых» данных и получить результат, неотличимый от профессионального.
Вывод: цели задаются по роли/типу инструмента, а не абсолютными числами.

## 2. Решения для flctrl

1. **Единица анализа — роль**, не дорожка: `drums / bass / guitar / keys /
   vocals / other` (`roles.py`). Роль определяется по имени, затем по спектру.
2. **Мера — слышимость**, не громкость: `A = N_partial / N_solo` по кадрам и
   полосам (`partial.py`). Громкость стема остаётся только для калибровки.
3. **Две ступени**: сначала внутри подгруппы (равная локальная слышимость),
   затем между подгруппами (профиль жанра + отношения маскировки).
4. **Цели — не медиана, а ансамбль.** Корпус хранится строками (по одному
   вектору на трек), а цель для проекта считается как взвешенная смесь k
   ближайших референсов с весами по расстоянию. Причина: у корпуса разные
   школы сведения, и среднее по всем просит правок, которых не хочет ни один
   живой микс. В ответе всегда есть список источников и их веса — видно, на
   кого равняемся (`balance.targets_for`).
5. **Правки с капом и предсказанием**: дБ считается через измеренную
   чувствительность `dN/dB`, а не «на глаз»; всё, что выше капа, режется.
6. **Приёмка только замером**: правка → повторный замер → accept/reject
   (`balance.check`, `judge`). Модель без проверки не считается доказательством.
7. **Переносимость** проверяется честно: модель строится на корпусе без одного
   трека и применяется к отложенному. Если на отложенном она просит большие
   правки — модель плохая, а не трек.

## 3. Обратная задача: цели по миксу, гейны — наши

Из стерео-референса роли не достать: разделение нейросетью врёт сильнее, чем
сам эффект. Поэтому цели берутся **на уровне микса** (28-полосный профиль,
резкость, crest, стерео), а неизвестные — гейны наших ролей (`invmix.py`).

Что важно знать по проверке:

- Семью областями задача **недоопределена**: разные балансы дают похожие доли.
  Переход на 28 полос сделал ответ однозначным (тест: восстановлены −3.5 против
  истинных −3.0 и +3.5 против +4.0, расстояние 0.84 → 0.00).
- **Общий уровень неидентифицируем**: калибровка нормализует громкость, поэтому
  любой равномерный сдвиг всех гейнов даёт тот же результат. Это не дефект —
  фейдеры относительны, важны разности.
- Глубина спуска имеет значение: при 4 проходах по 0.5 дБ решатель упирался в
  потолок и «не находил» ответ. Сейчас 14 проходов, кап 6 дБ.

## 4. Что из этого берём

- Единого объективного критерия «хорошего микса» нет; все метрики — прокси.
- Влияние нелинейных эффектов (сатурация, компрессия) на слышимость плохо
  предсказуемо аналитически — нужен замер после правки.
- Жанровые цели чувствительны к аранжировке: плотность и число дублей
  меняют распределение, поэтому выборка сравнимых секций обязательна.
- Панорама в плотном материале снимает маскировку сильнее фейдеров
  (Tom, Reiss, Depalle, AES 146, 2019) — порядок «фейдер, потом панорама»
  обоснован, но оптимум зависит от материала.
