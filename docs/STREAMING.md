# Потоковая обработка: разбор всех инструментов и устройство

Документ отвечает на вопрос «можно ли считать всё в потоке, без файлов». Короткий
ответ: **можно, но не всем и не на одной частоте** — и это должно быть видно в
данных, а не замазано.

## 1. Почему нельзя «просто в потоке»

| величина | значение |
|---|---|
| сырьё на дорожку | 44100 × 2 × 4 байта = 353 КБ/с |
| 32 дорожки | **11.3 МБ/с** (6-минутный трек — 4 ГБ) |
| блок | 256 кадров = 5.8 мс, **172 блока/с** |
| один RPC-вызов из Python | ~0.3–1 мс; 32 дорожки за круг ≈ 32 мс |
| опрос 30 Гц по 32 дорожкам | видим **~17 %** звука |

Отсюда два вывода:

1. Хранить звук целиком незачем: картина (метрики по времени) — десятки МБ
   против 4 ГБ сырья.
2. Опрос не может быть источником «точных» метрик: он видит лишь часть блоков.
   Точность надо либо обеспечить в колбэке, либо честно помечать.

## 2. Инвентарь: что у нас есть и что каждому нужно

Все текущие анализаторы принимают **путь к файлу** и считают STFT по всему
материалу (`bandprofile.band_axes`, `speech.intelligibility`, `wall.analyze`,
`transients.analyse`, `partial.bands29`, `harmony._spectra`,
`perceptual.band_levels`). Это офлайн-архитектура; для потока нужны
инкрементальные версии с состоянием.

| метрика | функция сейчас | что нужно от данных | в потоке |
|---|---|---|---|
| `rms` | `perceptual`/`partial` | сумма квадратов | **да, точно** |
| `peak` | — | максимум модуля | **да, точно** |
| `crest` | — | peak − rms | **да, точно** (из двух выше) |
| `lufs` | `perceptual.lufs` | K-взвешивание (IIR) + гейтирование | **да**, IIR хранит состояние |
| `bands` (28 полос) | `bandprofile.band_axes` | спектр блока (FFT 256) | **да**, FFT по блоку |
| `erb` | `perceptual.band_levels` | спектр + матрица ERB | **да** |
| `stereo` | `listen_layer.side_mid_db` | L/R по блокам | **да** |
| `masking` | `api.measure` | уровни полос по дорожкам | **да** (из `bands` парами) |
| `transient` | `transients.analyse` | огибающая + история 200 мс | **да**, с состоянием |
| `wall` | `wall.analyze` | спектр + медианы по секциям | **да**, скользящие медианы |
| `sections` | `wall`/`frames` | векторы признаков по окнам | **да**, инкрементально |
| `partial` (соны) | `partial.bands29` + `perceptual` | 29 полос + Zwicker | **да**, дороже (по окнам) |
| `sii` | `speech.intelligibility` | вокал + маскер, 18 полос | **по кольцу**, окнами 0.5–1 с |
| `harmony` | `harmony._spectra` | длинный спектр (строй/хрома) | **по кольцу**, окнами |
| IR / THD / дакинг | `effects.py` | импульс/синус/спец-сигнал | **нет, только офлайн** |
| сравнение с референсом | `frames.compare` | файл референса | **офлайн** (референс — файл) |

## 3. Три класса точности

Каждая строка картины помечается, чтобы не выдавать оценку за измерение:

* `exact` — посчитано на **каждом** блоке (колбэк, дешёвая арифметика, ≤8 каналов);
* `sampled` — по выборке блоков (опрос), поле `coverage` = доля увиденного звука;
* `windowed` — по кольцу раз в N секунд (SII, гармония, секции);
* `offline` — принципиально требует файла/спецсигнала.

## 4. Устройство

```
колбэк FL (JS)            Python (30–60 Гц)               картина
─────────────             ─────────────────               ───────
шины: sum/sumsq/peak  →   строка exact    ─┐
дорожки: hex-блок     →   FFT, полосы     ─┼→  rows[t] = {exact|sampled, bands, …}
кольцо 2–10 с (raw)   →   SII, гармония   ─┘        ↓
                                                   куб: время × дорожка × полоса
```

* **Кольцо** — единственное место, где лежит звук: 2–10 с, чтобы досчитать то,
  что требует сэмплов (транзиенты, SII, форма волны).
* **Анализаторы** — объекты с `feed(block)` и `value()`: IIR-фильтры, FFT на блок,
  огибающие, накопители хромы. Состояние маленькое, история не растёт.
* **Точный ярус** — только шины (мастер + роли): в колбэке считается сумма,
  сумма квадратов и пик, без выделения памяти на каждый блок.
* **Провенанс** — позиция в долях (мост, раз в 0.3–0.5 с) → клипы из разбора
  `.flp` → та же строка картины.

## 5. Как проверить, что поток не врёт

Обязательное условие, иначе это не измерение, а догадка:

1. взять известный WAV, прогнать через файловый анализатор — получить эталон;
2. прогнать тот же файл через потоковый анализатор (блоками 256) — получить ряд;
3. сверить: `rms`/`peak` — до 0.01 дБ, `bands` — до 0.1 дБ, `lufs` — до 0.1 LU,
   `transient` — совпадение онсетов в пределах одного блока.

Пока эта сверка не зелёная, метрика помечается `sampled` и в решения не идёт.

## 6. Что это меняет в API

Ничего не ломается: источником кадра становится не только файл, но и лента.

```python
cap = stream.run(seconds=20, exact=[0, 1, 2], tracks=range(32))
measure({"metric": "bands", "source": "cap1", "by": "section"})   # тот же кадр
compare("cap1", "ref")                                            # та же форма
```

Файлы — только явный экспорт (`cap.export(path)`), по умолчанию на диск ничего
не пишется.

## 7. Открытые вопросы

* Точный ярус на всех 32 дорожках: сколько стоит в колбэке (надо измерить, а не
  предполагать).
* Частота опроса против нагрузки: 60 Гц × 32 дорожки × FFT 256 — измерить.
* SII требует вокал и маскер отдельно — какие дорожки считать парой (роль
  `vocals` против суммы остальных).
* Порог, ниже которого `sampled` не используется в решениях (`decide.py`).
