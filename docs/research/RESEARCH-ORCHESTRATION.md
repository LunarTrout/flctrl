## 0. Соглашения

### 0.1 Метрики и знак

| метрика | смысл | хорошо |
|---|---|---|
| `lufs` | интегральная громкость ITU 1770 | = цель |
| `true_peak` | пик с пересэмплированием ×4, dBTP | ≤ −1.0 |
| `plr` | true_peak − lufs; **не зависит от гейна** | в коридоре рефов |
| `crest` | peak − RMS, дБ | в коридоре |
| `ldr` | разброс громкости по окнам 3 с, дБ | в коридоре (ниже = плотнее) |
| `sharp` | резкость (Zwicker), усреднённая | 1.6–1.7 |
| `regions` | 7 областей Барка, **доли в % от суммы** (в сумме 100) | = медиана рефов |
| `rel_db` | LUFS шины − LUFS мастера | = медиана рефов |
| `mi_db` | средний избыток маскера над маскируемым по активным полосам | **меньше = лучше** |
| `conflict_share` | доля активных полос, где избыток > 6 дБ | **меньше = лучше** |
| `buried_ratio` | доля полос, где остальные громче стема на 6+ дБ | меньше = лучше |
| `corr` / `width` / `mono_loss_db` | корреляция L/R, side/(mid+side)^0.5, потеря при суммировании в моно | в коридоре |

`mi_db` и `conflict_share` **асимметричны**: пара `A<-B` читается «B маскирует A». Оценка ставится по тому стему, который выводите вперёд, а не по паре вообще (см. 3.5).

### 0.2 Границы 7 областей — в герцах, а не по названию

Границы Барка: 0/2/5/9/14/18/21/24. Пересчёт `f = 600·sinh(z/6)`:

| область | Гц | кто хозяин |
|---|---|---|
| sub | 20–204 | бочка (низ), бас (саб), томы |
| bass | 204–533 | бас (тело), бочка (панч), корпус гитар, баян |
| lowmid | 533–926 | тело гитар, баян, тело вокала, малый |
| mid | 926–1765 | разборчивость вокала, «укус» гитар, треск малого |
| upmid | 1765–2689 | присутствие гитар и вокала, клик бочки |
| pres | 2689–4570 | атака тарелок, сибилянты, «шипение» гитар |
| air | 4570–8094 | тарелки, воздух, хвост реверба |

Профиль **не покрывает 8–20 кГц**. Де-эссер и «воздух» выше 8 кГц этим замером не видны — для них отдельный октавный замер (`octave_share`).

### 0.3 Перевод «пунктов доли» в децибелы

Доля нормирована, поэтому правка одной полосы на Δ дБ меняет её долю на

```
Δs ≈ s·(1−s)·ΔdB·ln10/10        →        ΔdB ≈ 4.343·Δs / (s·(1−s))
```

Для основных полос (s = 0.10–0.25) **1 пункт ≈ 0.23–0.48 дБ**; для узких (s = 0.05) — до 0.9 дБ. Отсюда правило: расхождение профиля 1–2 пункта — это меньше половины децибела, лечить эквалайзером; 4+ пункта — это аранжировка или баланс внутри инструмента, а не EQ.

### 0.4 Чего эти числа не умеют

- Профиль — **доли**, поэтому подъём одного стема автоматически «опускает» все остальные. Абсолютный уровень живёт в `rel_db`, форма — в `regions`. Это две независимые оси, и путать их — главная ошибка.
- `mi_db` считается по медианному спектру за окно. Внутритактовые конфликты (бочка против баса на 16-х) он не видит — только средний.
- Все замеры сделаны на 44.1/48 кГц рендерах без мастер-лимитера. После лимитера `crest`/`plr`/`ldr` меняются, профиль — почти нет.

## 1. Gain staging и целевые уровни

### 1.1 Три оси, которые нельзя смешивать

1. **Громкость** — `lufs` и `rel_db`. Отвечает на «кому добавить/убавить».
2. **Динамика** — `plr`, `crest`, `ldr`. Отвечает на «сколько компрессии».
3. **Форма** — `regions`. Отвечает на «где конфликт полос».

Одна ручка двигает обычно одну ось. Фейдер двигает громкость и (слабо) форму, компрессор — динамику и (слабо) форму, EQ — только форму. Поэтому и порядок правок такой: **форма → громкость → динамика** (см. 4.2).

### 1.4 Правила выставления уровней

1. **Цель — `rel_db`, а не абсолютный LUFS.** Абсолют зависит от мастеринга; относительный — свойство баланса.
2. Порядок: сначала форма инструмента (его собственный профиль), потом фейдер. Проверено: подъём барабанов +4 дБ без правки профиля уводит Σ|Δ| с 7.1 до **13.3** пункта, потому что у барабанов sub +3.8 пункта, и подъём раздувает именно его.
3. **Точный расчёт на компоненту**: чтобы доля `p` стала `t`, гейн `g = t/p` (в долях, не в пунктах). Для железа в барабанах: 9.7/2.0 = 4.85 → **+6.9 дБ**; бочка: 72.5/83.2 = 0.871 → **−0.6 дБ**. Это первое приближение: в SD3 железо и бочка не независимы (оверхеды ловят всё).
4. Один шаг — одна ручка. Замер после каждого. Порог суждения — шум метрики (1.6).
5. Запас: пик любой шины ≤ −6 dBFS, мастер до лимитера ≤ −6 dBFS, после лимитера TP ≤ −1.0 dBTP.

### 1.6 Мастер-цель — выводится, а не выбирается

`PLR = TP − LUFS` не зависит от гейна, поэтому это единственная честная цель. Рефы: PLR 7.40 (6.15…8.74). При TP = −1.0 dBTP:

```
LUFS_цель = TP − PLR = −1.0 − 7.40 = −8.4
```

**Цель: −8.4 ± 1 LUFS, TP ≤ −1.0 dBTP, crest 10.5–11.0.** Дефицит от текущего состояния: 11.59 − 7.40 = **4.2 дБ лимитирования/компрессии на 2-шине**. Гнаться за −6.5 LUFS рефов не нужно: стриминг всё равно нормирует к −14 [Р], а +2 дБ громкости стоит ещё 1.5–2 дБ crest.

## 2. Частотная оркестровка

### 2.1 Приоритет инструментов

Разрешение конфликта всегда в пользу верхнего в списке; уступает нижний.

| P | инструмент | что защищаем | почему |
|---|---|---|---|
| 1 | бочка | 50–100 Гц + клик 3–6 кГц | задаёт пульс, её пропажа читается как «нет драйва» |
| 2 | малый | 180–260 Гц тело + 3–5 кГц треск | спина грува |
| 3 | бас | 60–120 Гц фундамент | вес; но уступает бочке по времени (сайдчейн), а не по полосе |
| 4 | вокал/скрим | 200–400 Гц тело + 1–4 кГц разборчивость | в блэке часто сознательно утоплен (buried 0.915 у рефов) — не приоритет №1 |
| 5 | ритм-гитары | 100–200 Гц тело + 2–4 кГц «укус» | стена; широкая, легко уступает узким |
| 6 | баян/клавиши | 400–900 Гц | дублируемый слой |
| 7 | тарелки/атмосфера | 4.6–8 кГц | декорация |

Правило: **срезаем маскера, не поднимаем маскируемого.** Подъём на +3 дБ съедает запас и тянет за собой соседние полосы; срез на −3 дБ бесплатен по громкости.

### 2.2 Порядок разрешения конфликта

1. **Проверить, конфликт ли это.** `conflict_share` > 0.25 и `longest_run` > 30 полос — да, структурный. 0.05–0.1 — статистический шум, не трогать.
2. **Фейдер** (если разница `rel_db` > 1.5 дБ от цели) — самый дешёвый ход.
3. **EQ-срез** у маскера: 2–4 дБ, Q 1.0–1.5, максимум 6 дБ за проход. Не больше двух полос за шаг.
4. **Динамика**: сайдчейн (3.5) или динамический EQ, если конфликт только в моменты.
5. **Аранжировка**: развести по времени (пауза, октава), сменить позицию, убрать дубль. Это единственный метод, который чинит широкополосную маскировку.

## 3. Эффекты

### 3.0 Как проверять эффект объективно

Три универсальных теста, все выполняются офлайн через `sandbox.py` (pedalboard + VST3) до записи в проект.

**Импульс.** Подать дельта-функцию (один сэмпл 1.0), снять выход:
- **pre-delay** = позиция первого пика после сухого, мс;
- **время дилея** = позиция второго пика, мс → сверить с долей такта;
- **feedback** = 20·log10(пик3/пик2), дБ (−6 дБ ≈ 0.5, −12 дБ ≈ 0.25);
- **RT60** = наклон кривой Шредера (обратный интеграл энергии) по −60 дБ, с.

**THD.** Синус 1 кГц, уровень −18 dBFS, через плагин; БПФ, сумма амплитуд гармоник 2–10 к основной, в %. 0.5–3% — «плотность», 5%+ — слышимая грязь.

**Ducking.** Прогнать сухой сигнал с паузами; сравнить уровень возврата в паузе и под сигналом → глубина в дБ.

Плюс всегда: `fl_measure` до/после на одном и том же окне и `fl_judge` с шумами из 4.4.

### 3.1 Реверб

| параметр | значение | для блэка | проверка |
|---|---|---|---|
| архитектура | send/return, 100% wet | обязательно | — |
| pre-delay | 20–30 мс вокал [Р], 10–20 малый, 20–40 атмосфера | 15–25 мс на скрим: короче — муть, длиннее — отрыв от атаки | импульс |
| decay / RT60 | plate 0.8–1.4 с; room 0.5–0.8; hall 2.0–3.5 | вокал 0.9–1.4; атмосфера 2.5–3.5 | импульс |
| send | −18…−24 дБ от сухого (вокал), −24…−30 (гитары), −15…−20 (атмосфера) | чем плотнее аранжировка, тем тише send | замер возврата |
| HPF возврата | 300–400 Гц | обязательно, иначе lowmid-каша | профиль возврата |
| LPF возврата | 6–8 кГц | убирает «шипение» хвоста | профиль возврата |
| ducking | 3–6 дБ, attack 5 мс, release 150–250 мс [Р] | позволяет держать send мокрее без потери разборчивости | тест ducking |

Контроль ущерба: реверб поднимает пол между фразами → `ldr` стема становится менее отрицательным. **Допуск: ΔLDR ≤ 1.5 дБ.** Разборчивость: `stoi_score` вокала не ниже −0.02 от исходного (у нас база 0.553).

Типичная ошибка: реверб на гитарной шине. Стена из 4 гитар уже даёт плотность; send туда превращает upmid в шум. Реверб — на вокал, малый, баян, атмосферу.

### 3.2 Дилей

| параметр | значение | для блэка |
|---|---|---|
| время | 1/4, 1/8 с точкой, 1/8: `мс = 60000/BPM · доля` | 1/8 с точкой на лид/чистый вокал; на скрим обычно нет |
| feedback | 10–25% | 15% |
| mix / send | −24…−30 дБ | тише, чем кажется |
| фильтры | HPF 400 Гц, LPF 4–5 кГц | обязательно |
| стерео | ping-pong | проверить mono_loss |
| ducking | 3–4 дБ от сухого [Р] | да |

Пример: 180 BPM → 1/4 = 333 мс, 1/8 с точкой = 250 мс, 1/8 = 167 мс. Проверка импульсом: второй пик должен стоять ровно на расчётном времени ±2 мс.

### 3.3 Сатурация

| вид | гармоники | куда | THD |
|---|---|---|---|
| tape | нечётные, спад ВЧ, лёгкая компрессия | бас, шины, мастер | 1–3% |
| tube | чётные (2-я), асимметрия | вокал, баян | 0.5–2% |
| transformer | 3-я, поджатый низ | барабаны, бочка | 1–2% |
| diode / console | нечётные, жёстче | гитары (уже в ампах — не дублировать) | — |

Измерено на басе (drive 0…1):

| drive | LUFS | crest | вывод |
|---|---|---|---|
| 0.1 | −14.0 | **9.42** | безопасно (реф 9.83) |
| 0.3 | −12.5 | 7.92 | уже ниже медианы рефов |
| 0.6 | −10.5 | 5.93 | уничтожает динамику |

Правило: **сатурация баса не имеет права опустить crest ниже 9 дБ.** Прирост громкости при том же пике ≈ (crest_сух − crest_мокр) — то есть 0.3 «драйва» покупает 1.5 дБ громкости за 1.5 дБ динамики. Для блэка это допустимо только на басе и только до 9 дБ crest.

Где уместна: бас (плотность без громкости), drum bus (клей, 1–2% THD), вокал (присутствие, 0.5–1%), атмосфера. Где нет: гитарные шины (уже перегружены в ампах — второй слой даёт «фузз»), мастер до лимитера.

Мерить: THD синусом, `crest`, и «громкость при равном пике» — разница LUFS при выровненном TP.

### 3.4 Компрессия и параллельная

| инструмент | attack, мс | release, мс | ratio | GR, дБ |
|---|---|---|---|---|
| бочка | 10–20 | 60–120 | 3–6:1 | 3–6 |
| малый | 5–15 | 80–150 | 3–4:1 | 3–5 |
| бас | 20–40 | 100–200 | 3:1 | 3–6 |
| вокал | 5–15 | 80–150 | 3–4:1 | 4–8 |
| гитары | 20–30 | 100–200 | 2–3:1 | 2–4 |
| drum bus | 30 | 150–300 | 2:1 | 2–4 |
| 2-bus | 30–50 | 100–300 | 1.5–2:1 | 2–4 |

Проверено на басе: **−18 дБ, 3:1 → LUFS −18.52, crest 10.24** против рефов −18.14 / 9.83. Это валидированная настройка, можно ставить как есть. При −24 дБ / 4:1 LUFS падает до −22.9 — перебор.

Параллельная (NY) на барабаны: 1176-стиль, ratio 20:1, attack 1–3 мс, release 50–100 мс, бленд **20–40%**. Бленд подбирается не на слух, а по `crest`: он должен сесть в 15.5–17.5 (рефы барабанов 17.53).

Контроль: `crest`, `plr`, `ldr` до/после. Ожидаемое поведение — crest вниз на 2–4 дБ, LUFS вверх на 1–3 дБ, профиль без изменений больше 1 пункта.

### 3.5 Sidechain баса от бочки

| параметр | значение |
|---|---|
| глубина | 3–6 дБ |
| attack | 5–10 мс |
| release | 80–150 мс |
| ratio | 4:1+ |
| детектор | peak |

Измерено (3/6/9 дБ): проминентность бочки **+2.0 / +4.0 / +5.9 дБ**, цена **−0.16 / −0.27 / −0.36 LUFS**. Линейно: ≈ **+0.67 дБ проминентности на 1 дБ глубины**, ≈ **0.04 LUFS за 1 дБ**.

Рекомендация для нас: **6 дБ** — это +4 дБ к бочке за 0.27 LUFS, ровно то, чего не хватает (барабаны −4.4 дБ).

Ловушка метрики: после сайдчейна пара `BASS<-DRUM BUS` **ухудшается** (6.57 → 7.17 в пробе), потому что бас стал тише и бочка его сильнее перекрывает. Это не ошибка — просто мерили не ту сторону. Оценивать надо `DRUM BUS<-BASS` (проминентность бочки), а не пару «бас под бочкой».

### 3.6 Де-эссер

| параметр | значение |
|---|---|
| частота | женский вокал 6–7 кГц; мужской/скрим 3.5–5 кГц [Р] |
| диапазон | 4–8 кГц [Р] |
| GR | 3–6 дБ, только на пиках |
| ratio | 4:1 или split-band |

Проверка: доля 4.6–8 кГц (`air`) и `octave_share` на 4 кГц до/после; `sharp` не должен упасть больше 0.05. Если де-эссер срабатывает постоянно — проблема в источнике (микрофон/дистанция), а не в обработке.

### 3.7 Стерео

| приём | правило | проверка |
|---|---|---|
| низ моно | всё ниже 100–150 Гц в центре [Р] | `corr` баса = 1.000, `width` ≤ 0.05 (у нас 1.000 / 0.013 ✔) |
| ритм-гитары | 2 дубля L / 2 дубля R, пан 80–100%, **без Haas** | `corr` гитарных шин ≈ 0 |
| Haas | 10–25 мс, **только лид/клавиши**; первый провал при 10 мс — гребёнка [Р] | `mono_loss_db` ≥ −1.5 |
| M/S EQ | срез side ниже 150 Гц; +1…+2 дБ side в 2–5 кГц для ширины | `width`, `side_mid_db` |
| моно-совместимость | потеря при суммировании ≤ 1.5 дБ | `mono_loss_db` |

Наши значения: corr 0.473, width 0.513, mono loss −1.327 — всё в коридоре. По стерео делать нечего, кроме выравнивания GTR R к GTR L по уровню.

Ориентир по стемам: «other» у рефов широкий (`width` 0.657) и за это платит 2.5 дБ в моно; вокал и барабаны — умеренные (0.33 / 0.30); бас — моно.

## 4. Карта микса и приёмка

### 4.1 Формат строки

```
инструмент | цель (число + метрика) | текущее | дельта | действие | чем мерить | приёмка
```

### 4.2 Алгоритм обхода

1. **Собрать «до»**: `fl_measure` по секции (не по всему треку — секции разные), `fl_masking`, `fl_stems`, `fl_profile`.
2. **Посчитать три дельты на шину**: `Δrel = rel − ref`, `Δprofile = Σ|share − ref|`, `Δmask = conflict_share` по приоритетной паре.
3. **Отсортировать** по `|Δrel|/1.5 + Δprofile/4 + Δmask/0.25` — это «во сколько порогов» вышли. Первым чинится то, что дальше всех.
4. **Порядок правок**: форма инструмента → уровень → динамика → эффекты. Причина измерена: уровень без формы ухудшает Σ|Δ| (2.3).
5. **Один шаг — одна ручка.** После каждого: `fl_measure` в том же окне, `fl_judge`.
6. **Откат** при вето: `fl_rollback_last_change`.

Псевдокод прохода:

```python
for bus in sorted(buses, key=severity, reverse=True):
    if abs(rel[bus] - ref_rel[bus]) > 1.5:          # уровень
        move_fader(bus, ref_rel[bus] - rel[bus])
    for band, excess in profile_excess(bus).items(): # форма
        if excess > 2.0:                             # пункты
            eq(bus, hz=band_center(band), db=-db_for(excess, share[band]), q=1.2)
    if conflict[pair] > 0.25:                        # маскировка
        sidechain_or_cut(masker)
    judge(before, after, goals, corridor)            # принять/отклонить
```

### 4.3 Формулы для расчёта правки

```
доля → дБ:        ΔdB = 4.343 · Δs / (s·(1−s))
компонента → доля: g = t / p          (гейн в долях)
Σ|Δ| профиля:      sum(abs(share − ref))
маскировка:        exc[z] = max(0, masker_db[z] − masked_db[z])
                   mi = mean(exc[active]),  conflict = share(exc > 6)
цель мастера:      LUFS = TP − PLR_ref
```

### 4.4 Приёмка

`fl_judge` возвращает `accept` / `reject` / `insufficient`. Шумы метрик — ниже них судить нельзя:

| метрика | шум |
|---|---|
| `lufs` | 0.1 |
| `crest_db` | 0.2 |
| `ldr_db` | 0.5 |
| `sharp_mean` | 0.01 |
| `stereo.corr` | 0.005 |
| `stereo.side_mid_db` | 0.2 |
| `N_mean`, `phon_mean` | 0.5 |
| `octave_4k_db` | 0.2 |
| прочее | 0.3 |

**Вето**: если метрика ушла дальше от коридора — `reject`, даже когда цель достигнута. Это главное правило: локальное улучшение ценой выхода из коридора не принимается.

**Глобальный критерий «стало гармоничнее»** — четыре числа, все должны не ухудшиться:

| # | критерий | порог | у нас сейчас |
|---|---|---|---|
| 1 | Σ\|Δ\| профиля мастера к медиане рефов | ≤ 4.0 и не растёт | **4.1** |
| 2 | max \|rel_db − ref\| по стемам | ≤ 1.5 дБ | **4.4** (барабаны) |
| 3 | `conflict_share` приоритетной пары | ↓ ≥ 0.03, ни одна другая не выросла > 0.05 | 0.34 (бас←бочка) |
| 4 | `crest` / `PLR` / `LDR` | в коридоре рефов ±1.5 дБ | crest +3.7, PLR +4.2 — вне |

Плюс два стража: `true_peak ≤ −1.0` и `mono_loss ≥ −1.5`.

Пока критерий 4 вне коридора, любые правки профиля — косметика: миксу не хватает 4 дБ динамической обработки, а не эквалайзера.
