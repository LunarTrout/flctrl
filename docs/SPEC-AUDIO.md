# SPEC-AUDIO: запись всех дорожек из памяти и провенанс плейлиста

Домен AUDIO. Отвечает на два вопроса, которые мы обсуждали:

1. Как получить звук **каждой** дорожки микшера, не рендеря проект и не делая
   соло-проходов.
2. Как в каждый момент знать, **из чего** складывается звук дорожки: какие
   клипы, ноты и хвосты, и в каком месте **своего** материала они играют.

SPEC-LIVE описывает, как читать память, не мешая FL. Здесь — что именно
читается, как пишется на диск и как связывается с плейлистом.

## 1. Что читает tap

**С дорожки микшера (все дорожки, включая мастер):**

| величина | частота | зачем |
|---|---|---|
| буфер L/R, float32, блок N | поблочно | звук, спектр, маскировка, запись |
| размер блока и частота | при старте и при смене | пересчёт времени |
| пик и RMS | по блоку | метры, быстрый контроль |
| mute/solo/громкость/панорама | при изменении | понять, почему тихо |
| метры плагинов (если есть) | по блоку | GR компрессора, уровень реверба |

**Транспорт и время:**

- позиция в сэмплах (счётчик движка), секунды, такт;
- темп точный, размер, состояние петли;
- карта смен темпа (если есть автоматизация темпа);
- события: старт, стоп, переход, смена петли.

**Плейлист и каналы (структура, читается при изменении):**

- клипы: дорожка плейлиста, позиция, длина, **смещение внутри сэмпла**,
  источник (файл или паттерн), gain, фейды, mute;
- паттерны: список нот с локальным временем, канал, pitch, длина, velocity;
- каналы рэка: имя, сэмпл/инструмент, громкость, панорама, целевая дорожка;
- хвосты: RT60 по шинам и уровень, чтобы понимать, что звучит после клипа.

## 2. Запись на диск

**Формат.** WAV, 32-bit float, частота проекта, по файлу на дорожку. Мастер —
отдельным файлом.

**Поток.** tap → кольцевой буфер (2–3 с) → писатель. Писатель не блокирует tap:
если диск не успевает, блоки помечаются потерянными, а не выкидываются молча.

**Разбиение на сегменты.** Файл на сегмент (по умолчанию 60 с или по границе
петли/остановки). Имя: `<проект>_<дорожка>_<начало в сэмплах>.wav`.

**Якоря времени.** У каждого сегмента в заголовке (sidecar JSON): номер первого
сэмпла, позиция в проекте, темп, версия проекта, `tap_seq`. По ним сегменты
склеиваются без дрейфа.

**Политика пропусков.** Потерянные блоки — явные маркеры с диапазоном сэмплов.
Склейка через дыру запрещена: анализ помечает участок как неполный.

**Бюджет.** Ограничение по диску (по умолчанию 20 ГБ). При переполнении —
остановка записи с явной ошибкой, а не тихое удаление.

## 3. Провенанс: от дорожки к источникам

Для каждого момента времени по каждой дорожке:

```
track 12 (GTR L BUS), t = 114.01 с (сэмпл 5 472 512)
  ├ клип #1847: guitar_L_03.wav, локально 12.7 с из 31.0, gain −1.5 дБ
  ├ клип #1902: тот же файл, локально 0.4 с, gain −1.5 дБ
  ├ хвост: реверб от клипа #1801, RT60 1.4 с, −18 дБ
  └ канал: "Fortin L" → сэмпл тот же, обработка в слотах
```

Правила:

- **локальное время источника** считается в сэмплах: `позиция − начало клипа +
  смещение в файле`, с учётом растяжения, если оно есть;
- **несколько источников** на дорожку — нормальный случай, список, а не один;
- **хвосты** входят в список: клип кончился, звук нет;
- **MIDI**: паттерн → ноты, попавшие в момент (с учётом длины), → канал →
  инструмент;
- **актуальность**: структура читается из памяти, поэтому соответствует тому,
  что в проекте сейчас, а не тому, что сохранено;
- **пропуск**: если структура не прочитана, поле помечается `unknown`, а не
  заполняется догадкой.

## 4. Синхронизация и разрывы

- блоки выровнены по счётчику позиции; порядковый номер блока — часть записи;
- петля: при переходе через границу ставится маркер `loop_wrap`, данные не
  склеиваются;
- смена темпа: маркер `tempo_change` с новым значением; сетка тактов считается
  кусочно;
- остановка/старт: маркер `transport_stop/start`;
- если блоков не хватает — участок помечается `gap` с диапазоном.

## 5. Что отдаётся наружу

1. **Аудио**: сегменты WAV + sidecar с якорями (для анализа и прослушивания).
2. **Матрица**: строки по 50 мс — RMS, пик, полосы ERB, ширина, транзиент по
   каждой дорожке (SPEC-EAR).
3. **События**: разрешение блока вокруг атак и переходов.
4. **Провенанс**: карта клипов/нот/хвостов, привязанная к сэмплам.

## 6. Что проверять

1. **Выравнивание**: запись 32 дорожек за 60 с; сумма дорожек против мастера —
   корреляция > 0.99, задержка 0 сэмплов.
2. **Непрерывность**: нет дыр без маркера; при искусственной потере блока
   появляется `gap`, а не тишина.
3. **Провенанс**: для клипа известной длины локальное время совпадает с
   расчётным на нескольких позициях.
4. **Память**: 10 минут записи — потребление памяти tap не растёт (кольцо
   ограничено).
5. **Пассивность**: во время записи FL не меняет состояние проекта.
6. **Диск**: переполнение бюджета останавливает запись с ошибкой.

## 7. Чего спека не обещает

- Пока не гарантирует аудио **после каждого слота** (post-plugin) — это
  отдельная задача, буферы слотов нужно искать отдельно.
- Не обещает запись при закрытом проекте: источник — живой процесс.
- Не решает, что с данными делать: анализ — в SPEC-EAR, решения — выше.
