# SPEC — единая спека библиотеки

Один живой документ. Всё остальное — история: `docs/ARCHIVE.md` (указатель,
последние сверху) и `docs/archive/` (34 прежних документа + прежние версии спек).

---

## 1. Требование

> Из микшера в лайве получать **все дорожки** и понимать, из чего они состоят:
> из каких **клипов и MIDI**, и **в какой момент их времени**.

Развёрнуто: по любой дорожке в любой момент — **знать состав** (клипы, ноты,
хвосты, локальное время источника), **знать обработку** (плагины, автоматизация),
**знать восприятие** (частичная громкость, маскировка, транзиент, стерео) и
**уметь менять** с предсказуемым результатом и проверкой числом.

| часть требования | что значит технически |
|---|---|
| «все дорожки» | каждая дорожка микшера, включая мастер, без подмножеств |
| «из чего состоят» | источники на дорожку: аудиоклипы, MIDI-ноты, хвосты эффектов |
| «в какой момент их времени» | локальное время внутри источника (сэмпл файла / позиция в паттерне) |
| «в лайве» | из живого процесса, без рендера и соло-проходов, актуально текущему состоянию |

## 2. Принципы

1. Факты, не советы: числа, единицы, база сравнения, покрытие.
2. Сравнение вместо объяснений: две картины одной формы → дельта по осям.
3. Инвариантность: метрика не зависит от числа дорожек и общего уровня.
4. Провенанс: у числа есть адрес — из чего сложилось, чем обработано, где слушать.
5. Пропуск виден: отсутствие данных помечается, никогда не ноль.
6. Сначала ресёрч, потом реализация. Никаких слепых `sleep`.

## 4. Дерево и адресация

Всё — один объект, у каждого узла путь:

```
/project            имя, темп
/transport          playing, position, seconds, tempo, loop
/track/{i}          name, volume, pan, mute, solo
/track/{i}/slot/{s}              плагин
/track/{i}/slot/{s}/param/{p}    параметр (значение + подпись)
/track/{i}/slot/{s}/band/{b}     полоса EQ (hz, gain, q)
/track/{i}/send/{d}              посыл
/channel/{i}        канал рэка → target_track
/playlist/clip/{id} клип: track, position, length, source_offset, sample
/section            рабочее окно
/refs/{name}        референс
/measure/{id}       кадр замера
```

`*` — все узлы: `get("/track/*/volume")`. Ошибка — структурная:
`{ok:false, code:"range", path, allowed}`. Без «что делать».

## 5. Куб: одна форма для всех картин

```
оси: время (сэмпл → такт) × дорожка (→ роль) × полоса (ERB) × метрика
```

Матрица из потока — срез `rms[время, дорожка, полоса]`. Спектр файла — тот же
срез, посчитанный иначе. Референс — такой же куб.

- картина = проекция куба, сравнение = дельта по тем же осям;
- у клетки есть провенанс: источники → обработка → сырой отрезок;
- аддитивные метрики внутри роли суммируются, неаддитивные считаются как
  «роль против остального»;
- пропуск — явный, не ноль.

## 6. Гранулярность: у референсов нет 32 дорожек

- `roles.py` приводит проект к `drums / bass / guitar / keys / vocals / other`;
- референсы существуют на уровне ролей;
- сравнение — на самой грубой общей гранулярности (реф ↔ мы — роли; наш
  «до/после» — дорожки);
- метрика инвариантна: `роль / остальное`.

## 7. Обход разделения референсов

Разделение стемов — слабое звено. Основной путь — **обратная задача**
(`invmix.py`): цели микса с референса, неизвестные — гейны наших настоящих
дорожек, сумма должна попасть в целевой вектор. Цели по ролям — побочный
продукт решения. Стемы референса — только перекрёстная проверка с метрикой
качества (ошибка реконструкции + протечка). `snr_baseline.json` из стемов —
приблизительный, подлежит замене.

## 8. Доступ к живому FL: три класса

| класс | что | координация |
|---|---|---|
| passive read (tap) | память процесса: позиция, темп, буферы, метры, структура | не нужна, FL не трогает |
| control write | громкость, панорама, параметры, слоты, транспорт | очередь, `project_version` растёт |
| exclusive lease | рендер, смена проекта, перезапуск | аренда на всех, остальные `busy` |

Tap читает пассивно: один процесс, много потребителей через memmap/сокет;
отвалился — потребители видят `stale`, а не висят.

## 9. Запись всех дорожек и провенанс

**Что читается:** буферы L/R float32 поблочно по каждой дорожке и мастеру;
метры; точная позиция в сэмплах; точный темп и карта его смен; клипы со
**смещением внутри сэмпла**; ноты паттернов; каналы → дорожки; хвосты (RT60).

**Запись:** WAV float32, файл на дорожку, сегменты по 60 с или по границе;
sidecar с якорями (первый сэмпл, позиция, темп, версия). Потерянные блоки —
маркеры `gap`, склейка через дыру запрещена. Бюджет диска — с явной остановкой.

**Провенанс на момент времени:**

```
track 12 (GTR L BUS), t = 114.01 с (сэмпл 5 472 512)
  ├ клип #1847: guitar_L_03.wav, локально 12.7 с из 31.0, gain −1.5 дБ
  ├ клип #1902: тот же файл, локально 0.4 с, gain −1.5 дБ
  ├ хвост: реверб от клипа #1801, RT60 1.4 с, −18 дБ
  └ канал "Fortin L" → сэмпл, обработка в слотах
```

Несколько источников на дорожку — норма. Хвосты входят в список. Структура
читается из памяти, поэтому соответствует текущему состоянию, а не файлу.

## 10. Интерфейс: пути и шесть глаголов

```
list(path)            что лежит и какого типа
get(path)             значение
set(path, value)      записать (пачка — атомарно, с откатом)
call(op, args)        действие: plugin.insert/delete/replace, transport, save, track.add
measure(spec)         метрика → кадр
compare(a, b)         дельты по осям
```

Свойства, не глаголы: `dry_run`, `undo`. MCP-поверхность — те же шесть плюс
`undo`/`dry_run`; старые 77 имён остаются обёртками.

Реестр метрик: `rms`, `peak`, `crest`, `bands` (240 Барка), `erb`, `partial`,
`masking`, `sii`, `transient`, `harmony`, `stereo`, `wall`, `sections`, `lufs`.
Метрика — строка реестра (оси, единицы, источник), а не инструмент.

### 10.1. Контракт: что чем выражается

| группа | пути / операции |
|---|---|
| состояние | `list("/")`, `get("/project")`, `get("/track/*")`, `get("/track/{i}/slot")`, `get("/channel/*")`, `get("/playlist/clip/*")`, `get("/transport")` |
| значения | `set("/track/{i}/volume|pan|mute|solo")`, `set("/track/{i}/slot/{s}/param/{p}")`, `set("/track/{i}/slot/{s}/band/{b}", {hz,gain,q})`, `set("/track/{i}/send/{d}", {active,level})` |
| действия | `call("plugin.insert|delete|replace")`, `call("track.add|delete")`, `call("save")`, `call("render")`, `call("transport.play|stop")` |
| запись | `call("record.start", {tracks, path})`, `call("record.stop")`; читается как `get("/record/{id}")` |
| слух | `measure({metric, by, where, source})`, `compare(a, b)` |
| референсы | `get("/refs")`, `measure({..., source:"/refs/GRIMA"})` |
| решения | `call("plan.build", {diff})`, `call("plan.apply", {plan})`, `call("verify", {change})` |
| система | `call("system.health|doctor|reset")`, `call("lease.take|release")` |

Правило: ни одна операция не задаёт порядок работы. `set` работает без
`measure`, `compare` — без `plan`, `measure` — без `set`.

Замещение старых имён (77 инструментов) — механическое: `fl_tracks` →
`get("/track/*")`, `fl_set_volume` → `set("/track/N/volume")`, `fl_wall` →
`measure({metric:"wall"})`, `fl_apply_plan` → `call("plan.apply")`. Пока новые
не покрыли всё, старые остаются обёртками.

## 11. Чего не хватает (сжато)

Полный реестр — §3 в `docs/archive/specs-03-11/SPEC-CONTEXT.md`. Главное:

1. **звук дорожек** (tap) — блокер всего;
2. точная позиция в сэмплах и точный темп;
3. смещение внутри сэмпла и фейды клипа; свежесть карты;
4. ноты из паттернов;
5. хвосты и мастер;
6. метры плагинов, пресеты, bypass;
7. автоматизация: чтение и запись;
8. рендер без закрытия проекта, VST в слот, создание каналов.

## 12. Порядок работ

1. поток аудио с дорожек в стерео + запись на диск;
2. точная позиция и темп;
3. провенанс: смещение в сэмпле, свежесть;
4. ноты из паттернов;
5. хвосты и мастер;
6. восприятие по записанным дорожкам (файловые метрики уже есть);
7. метры плагинов и автоматизация.

## 13. Критерий готовности

Первый рубеж: **любой участок любой дорожки пишется в файл без рендера проекта
и без соло-проходов**, с точной позицией и темпом, и по нему видно, из каких
клипов и MIDI он сложился и в какой момент их времени.

Полная система отвечает числами без рендера на шесть вопросов: что звучит и
откуда; насколько слышно; кто маскирует; что делает плагин; насколько далеко от
жанра; что будет, если изменить.
