# flctrl — сведение по измерениям для FL Studio

`flctrl` — библиотека на Python, которая даёт машине *слышать* проект FL Studio так, как
слышит инженер: снимает звук **каждой дорожки микшера вживую**, превращает его в плотное,
но читаемое описание («ленту»), ловит короткие события, которые размазал бы кадр в 100 мс,
и сравнивает любые две картины по одним и тем же осям.

Она существует из-за одного упрямого ограничения: **референсы приходят одним стереофайлом,
стемов нет и не будет.** Поэтому библиотека никогда не пытается разделить референс. Она
измеряет его в тех же единицах, что и свой микс, и решает обратную задачу: какие гейны,
EQ и панорамы заставят *наши* дорожки просуммироваться в числа референса.

## Какую задачу решает

Сводить на слух по референсу долго и невоспроизводимо. Сводить по числам обычно не
получается по другой причине: числа описывают *мастер*, а у референса дорожек нет вовсе.
`flctrl` закрывает разрыв с двух сторон.

| Сторона | Что есть | Что делаем |
|---|---|---|
| Наш проект | 29 дорожек микшера, доступна любая ручка | снимаем каждую дорожку вживую, измеряем, храним числа |
| Референс | один стереофайл, стемов нет | измеряем тем же кодом, теми же полосами, той же сеткой времени |
| Сравнение | источники разные | кладём оба в один куб (`время × дорожка/роль × полоса × метрика`) и вычитаем |

Всё остальное — EQ-ходы, планы панорамы, обратный решатель — потребляет эти числа, а не
догадки.

## Три идеи

**Куб.** Любое измерение имеет одну форму: `время × дорожка (или роль) × полоса ×
метрика`. Кадр — это двумерный срез с именованными осями, единицами и явным покрытием
(`frames.make_frame`). Пропуск — `None`, никогда не ноль, поэтому сравнение это вычитание,
а не особый случай.

**Лента.** На каждую дорожку, на каждую клетку 0.1 с — полный вектор признаков: 28
третьоктавных полос, 24 ERB-полосы, громкость, тембровые дескрипторы, высота, гармония,
стерео, динамика. Около 1 КБ на клетку — на три порядка меньше самого звука (14.5 КБ в
секунду на дорожку против ~350 КБ стерео float 44.1 кГц).

**События.** Клетка в 100 мс не может изобразить удар бластбита длиной 20 мс. Отдельный
проход с шагом 2 мс выдаёт короткие события — онсеты, скачки уровня, клиппинг — с пиком,
длительностью, крестом, полосой и центроидом. Измерено: **39 из 40 ударов на 300 BPM,
32-е (через 25 мс)**.

## Требования

- Windows 10/11 (живой захват опирается на Disk Recording в FL и реестр Windows)
- FL Studio 2025 (проверено на 25.2.5 build 5319, Producer Edition)
- Python 3.12 для живого пути: `frida`, `numpy`, `scipy`, `soundfile`, `pytest`
- Мост контроллера FL на `127.0.0.1:9787` (см. соседний репозиторий MCP)
- Встроенный в FL **Disk Recording** — без плагинов и ручной настройки проекта

Офлайн-работа (файлы, референсы, кадры) требует только `numpy` + `scipy` + `soundfile`.

## Быстрый старт

```python
import sys
sys.path.insert(0, r"C:/путь/до/flstudio-lib/flctrl")

from flctrl import api, live

# Снять все дорожки микшера за 2 секунды, начиная с 8-го такта
res = api.call("tracks.live", {"seconds": 2.0, "start": 8.0})

for tid, tr in res["tracks"].items():
    print(tid, tr["name"], tr["role"], tr["rms"], tr["peak"],
          tr["transients"]["onsets_s"])

print(res["masking"]["pairs"][:5])     # кто кого перекрывает
print(res["provenance"][:3])           # что звучит в проекте, каждые 0.5 с

# Сам звук — только по явному запросу, никогда как побочный эффект
files = api.call("tracks.dump", {"tracks": [1, 12], "seconds": 5.0,
                                 "outdir": r"C:/tmp/stems", "fmt": "mp3"})["files"]
```

```python
# Любой файл проходит через тот же код: референс, рендер, стем
import soundfile as sf
from flctrl import timbre, events

x, fs = sf.read("reference.wav", always_2d=True)
tape = timbre.analyze(x, fs)   # клетки + LUFS + LRA + SII + гармония + проверки
ev = events.detect(x, fs)      # слой 2 мс
print(tape["lufs"], tape["lra"], tape["sii"], ev["count"])
```

## Живой захват

Две реализации с одинаковым выходом.

**`files` (по умолчанию, рекомендуется).** Сохраняем проект по Ctrl+S и копируем `.flp`
как точку восстановления, взводим дорожки, включаем запись, играем с `start`, читаем
WAV-файлы, которые написала FL, считаем ленту, удаляем их, снимаем взвод, возвращаем
прежний режим. Папка `Recorded` после этого пуста (проверено). FL остаётся живой, проект
не меняется — кроме состояния взвода, которое восстанавливается.

**`memory` (без диска).** Хук Frida на `CreateFileW`/`WriteFile` узнаёт файлы записи,
копирует PCM в память и обнуляет длину записи: FL считает, что записала, а на диск уходит
только 76-байтный заголовок (его убирает `live.clean()`). Хук живёт в долгоживущем демоне
(`tools-local/hook_daemon.py`, порт 9788), поэтому цепляется один раз за сессию. Это самый
чистый путь — и именно он иногда дестабилизировал FL в разработке, отсюда режим по
умолчанию.

Оба режима: без перезагрузки проекта, без модальных окон (окно «Recording» гасится через
`PopupRec`) и с точкой сохранения перед каждым снимком.

Подробно: [docs/LIVE.ru.md](docs/LIVE.ru.md) · [docs/LIVE.md](docs/LIVE.md)

## Лента

Клетка = 0.1 с, окно 4096 сэмплов (~93 мс). Поля клетки:

| Группа | Поля |
|---|---|
| Громкость | `rms_db`, `peak`, `crest_db`, `lufs_st` (BS.1770, блоки 400/100 мс) |
| Динамика | `attack_s`, `decay_db`, `flux_db`, `zcr`, `hits` |
| Спектр | `bands` (28 третьоктав), `erb` (24), `centroid_hz`, `spread_hz`, `flatness`, `rolloff_hz` |
| Тон | `f0_hz`, `note`, `hnr_db`, `chroma` (12), `harm` (2f0…6f0), `inharm`, `formants` |
| Полосы | `low_db`, `mid_db`, `high_db`, `decay_bands` (дБ/с), `wall` |
| Стерео | `corr`, `width`, `pan`, `coherence` (L/R по полосам) |

На дорожку: `lufs`, `lra`, `sii`, `harmony`, `checks` (DC, клипы, моно-корреляция),
`transients`, `mod_rate_hz`, `mod_depth`, `jitter_pct`, `technique`.
На снимок: `masking`, `provenance`, `position`.

Измеренные размеры: клетка ~1.0 КБ; дорожка за секунду 14.5 КБ; 29 дорожек × 10 с ≈ 4.1 МБ
(против 97.6 МБ сырого PCM).

Полный справочник: [docs/TAPE.ru.md](docs/TAPE.ru.md) · [docs/TAPE.md](docs/TAPE.md)

## События

`events.detect(stereo, fs)` считает огибающую окном 4 мс с шагом 2 мс и выдаёт `onset`
(рост ≥5 дБ после спада, рефрактерность 12 мс), `spike` (+15 дБ за 20 мс) и `clip`
(сэмплы на 0 дБFS). У каждого онсета — пик, длительность, крест, полоса, уровни полос и
центроид.

| Сигнал | Шаг | Поймано | Ожидалось |
|---|---|---|---|
| 300 BPM, 32-е | 25 мс | 39 | 40 |
| Тремоло 20 Гц | 50 мс | 19 | 20 |
| Тремоло 12 Гц | 83 мс | 11 | 12 |

## Точки сохранения

`live.save_project()` поднимает окно FL, посылает Ctrl+S, ждёт изменения mtime файла и
возвращает путь. `live.backup()` копирует его в `~/Backups/flctrl/`, пропускает
одинаковые состояния (по SHA-1) и держит 20 точек. Если сохранить не удалось — берётся
автосейв FL, и об этом честно пишется `origin: "autosave"`.

Восстановление — открыть снимок. История undo в FL живёт в памяти и умирает вместе с
процессом; эти точки переживают падение.

## Поверхность API

`flctrl.api.call(op, args)` — единственная точка входа; MCP-сервер заворачивает её в
десять инструментов. Полная таблица: [docs/API.ru.md](docs/API.ru.md) · [docs/API.md](docs/API.md).

| Операция | Что делает |
|---|---|
| `tracks.live` | снимок + лента + события + маскировка + провенанс |
| `tracks.dump` | явная выгрузка дорожек в WAV/MP3 |
| `measure` | метрики кадра, файла или живого потока |
| `compare` | дельта или коридор между кадрами |
| `clip.at` | что звучит в данную секунду/такт |
| `pan.plan`, `pan.move` | план и выполнение панорамы |
| `eq.set`, `plugin.insert/delete/replace` | правки обработки вживую |
| `stream.run` | поток метрик во время игры |
| `inverse.solve` | цели референса → гейны наших дорожек |
| `system.health`, `system.doctor` | проверка моста и библиотеки |

## Ограничения

- **Время в ленте** — 100 мс по замыслу; короткие события — работа слоя событий, а не клеток.
- **Частота** — 28 третьоктав или 24 ERB-полосы; мельче — дороже по размеру.
- **Высота** требует ≥2 периодов: 40 мс на 50 Гц. Быстрее `f0` недостоверен по построению.
- **Громкость** считается блоками 400 мс с шагом 100 мс, то есть `lufs_st` — кратковременная,
  а не мгновенная.
- **Живой захват требует режима записи** на время снимка: это снимок, а не непрерывный монитор.
- **Режим `memory`** без диска, но на FL 25.2.5 он был менее стабилен, чем `files`.

## Состояние

Проверено на реальном проекте (29 дорожек, FL 25.2.5): живой поканальный захват в обоих
режимах; полная лента; события до 40 в секунду; маскировка, провенанс, роли, точки
сохранения; и доказательство корреляцией, что снятые дорожки — не копии мастера
(GTR L1 ↔ GTR R1: 0.046; максимум 0.614 — это шина и её источник).

Дальше: построитель кадра референса (`reference.frame(path)`) и замкнутая петля
«измерил → решил → применил → измерил», описанная в
[docs/REFERENCE.ru.md](docs/REFERENCE.ru.md).
